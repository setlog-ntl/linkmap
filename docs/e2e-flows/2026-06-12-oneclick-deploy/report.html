5. 인사이트

① PL/pgSQL의 enum=TEXT 비교는 리터럴('free')은 통과하지만 변수 경유(COALESCE(v_plan,...))는 42883으로 죽는다 — RPC를 크리티컬 패스에 넣을 땐 프로덕션 스키마 타입으로 실행 검증이 필수.
② 정책 이중화는 드리프트를 낳는다 — 사전 체크(quota.ts, admin 바이패스 있음)와 DB RPC(없음)가 갈라져 관리자만 차단되는 버그 발생. 단일 소스 또는 계약 테스트 필요.
③ E2E가 아니면 못 잡는 버그였다 — 단위 테스트는 mock DB라 enum 타입 불일치를 통과시킴. 흐름 테스트 체계(docs/e2e-flows/)의 존재 가치를 첫 실행에서 실증.
