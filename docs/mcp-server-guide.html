01한눈에 보기

MCP 서버는 로컬 파일을 직접 읽지 않는다. 파일 탐색은 Claude Code가 하고, 서버는 해석과 저장만 담당한다.

02설정

프로젝트 루트 .mcp.json + 환경변수 2개가 전부다.

현재 리포지터리에 들어 있는 설정

// C:\Dev\linkmap\.mcp.json  (발췌)
{
  "mcpServers": {
    "linkmap": {
      "command": "npx",
      "args": ["tsx", "packages/mcp-server/src/index.ts"],
      "env": {
        "LINKMAP_API_URL": "https://www.linkmap.biz"
      }
    }
  }
}

토큰이 비어 있다. 현재 설정에는 LINKMAP_API_TOKEN 이 없다. 이 상태에서는 서버 API를 호출하는 모든 도구가 401로 실패하고, detect_services 만 로컬 매핑 테이블 결과로 동작한다. 다만 토큰을 .mcp.json에 직접 적으면 커밋되는 파일에 시크릿이 들어가므로 금지다 — 아래 3-② 방식을 쓴다.

환경변수

변수기본값필수역할
LINKMAP_API_URLhttps://www.linkmap.biz아니오호출 대상. 로컬 개발 시 http://localhost:3000
LINKMAP_API_TOKEN(없음)예stl_ 접두사 개인 액세스 토큰. 없으면 서버 연동 전부 401

토큰의 정체

/api/tokens 가 발급하는 개인 액세스 토큰이다. 구현상 특징:

  • 형식 stl_ + 랜덤 32바이트 hex — 발급 직후 1회만 원문이 노출된다.
  • DB에는 SHA-256 해시(api_tokens.token_hash)만 저장된다. 분실 시 복구 불가, 재발급만 가능.
  • 스코프: read / write / admin. 미지정 시 ['read','write'].
  • 만료: 1~365일 지정 가능, 미지정 시 무기한.
  • 발급에 MFA 통과가 강제된다(requireMfa). 2FA를 켜지 않았다면 먼저 설정해야 한다.
도구필요 스코프
detect_services (서버 2차 해석)read
sync_project_serviceswrite

03적용 방법

토큰 발급 → 환경변수 주입 → 세션 재시작 → 연결 확인 순서.

  1. 개인 액세스 토큰 발급

    linkmap.biz/settings/developer → API 토큰 → 새 토큰. 이름은 용도로 (claude-code-local), 스코프는 read + write, 만료는 90일 권장. 표시된 stl_… 값을 이때 복사한다 — 다시 볼 수 없다.

  2. 토큰을 셸 환경변수로 주입 (파일에 쓰지 않는다)

    .mcp.json 은 git에 커밋되므로 토큰을 넣지 않는다. Claude Code를 띄우는 셸 세션에 넣는다.

    # PowerShell — 현재 세션
$env:LINKMAP_API_TOKEN = "stl_...."

# PowerShell — 사용자 계정에 영구 등록 (한 번만)
[Environment]::SetEnvironmentVariable("LINKMAP_API_TOKEN", "stl_....", "User")

    .mcp.json 의 env 블록에 없는 변수도 자식 프로세스가 부모 셸 환경을 상속하므로 그대로 전달된다.

  3. Claude Code 재시작 후 연결 확인

    /mcp 를 실행해 linkmap 이 connected 로 뜨는지 본다. 도구는 mcp__linkmap__* 이름으로 노출된다. 서버 부팅 로그는 stderr로 Linkmap MCP Server v0.3.0 started.

  4. 대상 프로젝트 UUID 확보

    동기화 계열 도구는 전부 project_id(UUID)를 요구한다. Linkmap 웹의 프로젝트 상세 URL /project/<uuid> 에서 복사한다.

  5. 실행

    Claude Code에 자연어로 지시하면 된다. 내장 sync-guide 프롬프트가 절차를 안내한다.

    "이 프로젝트에서 쓰는 외부 서비스를 찾아서
 Linkmap 프로젝트 <uuid> 에 동기화해줘"

다른 클라이언트 (Cursor 등) · 전역 설치

{
  "mcpServers": {
    "linkmap": {
      "command": "npx",
      "args": ["tsx", "C:/Dev/linkmap/packages/mcp-server/src/index.ts"],
      "env": { "LINKMAP_API_URL": "https://www.linkmap.biz" }
    }
  }
}

package.json 에 bin: linkmap-mcp → dist/index.js 가 선언되어 있으므로, npm run build 후에는 빌드 산출물을 직접 실행하는 형태로도 등록할 수 있다(현재 npm 레지스트리에 배포되어 있지는 않다).

04연결되면 가능해지는 것

도구 8개 · 리소스 2개 · 프롬프트 1개가 노출된다. 다만 실제로 동작하는 것은 이 중 일부다 — 05장 참조.

도구하는 일호출 대상상태
detect_services 패키지명·환경변수 키·설정 파일명을 서비스 slug로 변환. 로컬 테이블 1차 → 미매칭만 서버 2차. 신뢰도(high/medium/none)와 출처를 함께 반환 로컬 + POST /api/mcp/detect 동작
sync_project_services 매핑된 slug를 프로젝트에 반영. 기존 연결과 비교해 차분만 INSERT, 카탈로그에 없는 slug는 옵션에 따라 커스텀 서비스로 자동 생성. 결과를 added / already_exists / not_found / custom_created 로 분류 POST /api/mcp/sync 동작
list_services 서비스 카탈로그 전체 조회 (카테고리 필터) GET /api/services 라우트 없음
get_project_services 프로젝트에 연결된 서비스 목록 조회 GET /api/projects/[id]/services 라우트 없음
get_env_vars 환경변수 이름만 조회 (값 제외) GET /api/projects/[id]/env 경로 불일치
search_packages 서비스 패키지 레지스트리 검색 GET /api/packages 미구현
install_package 패키지 설치 — 포함 서비스 일괄 추가 + 환경변수 템플릿 생성 POST /api/packages/install 미구현
export_package 프로젝트 구성을 linkmap.json 으로 내보내기 POST /api/packages/export 미구현
리소스 / 프롬프트내용상태
linkmap://detection/npm-mapnpm 패키지 → slug 매핑 테이블 전문 (약 120개 항목, 로컬 상수)동작
linkmap://catalog/services전체 서비스 카탈로그라우트 없음
sync-guide (프롬프트)탐색 → 매핑 → 동기화 3단계 안내. "값은 전송 금지, 키 이름만" 규칙 포함동작

05현재 상태 점검 — 실제로 쓸 수 있는 범위

선언된 도구 8개 중 6개가 존재하지 않는 API 엔드포인트를 호출한다. 호출 시 Linkmap API error 404 로 실패한다. 소스 기준 확인 결과:

  • src/app/api/services/route.ts — 없음 (services/custom/ 만 존재)
  • src/app/api/projects/[id]/services/route.ts — 없음 (하위 [psId]/cost, [psId]/usage 만 존재)
  • src/app/api/projects/[id]/env/route.ts — 없음. 환경변수 API는 /api/env 로 별도 구성되어 있어 MCP 서버가 잘못된 경로를 호출한다
  • src/app/api/packages/** — 디렉터리 자체가 없음 (search / install / export 3종 전부)

즉 현재 실사용 가능한 기능은 「서비스 탐지 → 프로젝트 동기화」 한 줄기다. 이것이 MCP 서버의 핵심 가치이므로 실용성은 있지만, 나머지 도구는 모델에게 노출된 채 실패하므로 오작동으로 인식될 수 있다.

부수적으로 확인된 사항 2건

① detect_services 의 서버 폴백 병합은 요청과 응답의 배열 순서가 동일하다고 가정하고 인덱스로 짝을 맞춘다. 서버가 순서를 바꾸거나 항목을 누락하면 slug가 엉뚱한 힌트에 붙는다.

② sync_project_services 의 create_custom_for_unmatched: true 는 오타난 slug까지 커스텀 서비스로 만들어 카탈로그를 오염시킨다. 기본값 false 를 유지하고, 켤 때는 not_found 목록을 먼저 확인하는 편이 안전하다.

권장 조치 (선택지)

방향내용비용
A. 도구 축소깨진 6개를 index.ts 에서 제거하고 v0.4로 릴리스. 모델에게 실패하는 도구를 노출하지 않는 것이 가장 확실하다낮음
B. 경로 교정get_env_vars 를 실제 존재하는 /api/env 계약에 맞춰 수정. 나머지는 A와 동일 처리낮음~중간
C. 백엔드 구현/api/services, /api/projects/[id]/services, /api/packages/* 를 토큰 인증 기반으로 신규 구현높음

06보안 모델

인증
Bearer stl_ 토큰 → SHA-256 해시 대조. 만료 검사 후 last_used_at 갱신
인가
스코프 검사(hasScope) + 프로젝트 소유권 검사(project.user_id !== auth.userId → 403)
DB 접근
서버 라우트는 createAdminClient() 사용 — RLS를 우회하므로 위 소유권 검사가 유일한 방어선
감사 로그
mcp.detect / mcp.sync_services 를 logAudit 로 기록 (힌트 수·매칭 수·slug 목록)
비밀 정보
환경변수 값은 전송·저장 대상이 아니다. 키 이름만 오간다

운영 시 지킬 것 — 토큰은 .mcp.json·.env 커밋 대상 파일이 아닌 셸 환경변수에 둔다 · 만료를 반드시 설정한다 · 유출 의심 시 /settings/developer 에서 즉시 폐기 후 재발급한다.
