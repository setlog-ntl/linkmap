핵심 진단: Linkmap은 외부 연동의 기반 인프라가 모두 완비되어 있다 — OAuth 범용 프레임워크, AES-256-GCM 토큰 암호화, 헬스체크 어댑터 패턴, 환경변수 충돌 감지, 자동 연결 제안. 그러나 90+개 카탈로그 서비스 중 실제 API 호출이 동작하는 것은 3개뿐이며, MCP 서버는 6개 tool 중 3개의 백엔드가 미구현 상태이다.

권고 방향: Phase 1에서 기존 인프라를 최대한 활용(헬스체크 어댑터 확장 + OAuth 프로바이더 추가)하여 빠르게 연동 서비스 수를 늘리고, Phase 2에서 MCP 서버 + 패키지 레지스트리를 구축하여 AI-first 개발자 경험(DX)으로 차별화한다.

2. 현황 분석 (As-Is)

2.1 인증 체계 현황

OAuth 프레임워크 (범용 구조)

src/app/api/oauth/[provider]/의 동적 라우트로 설정만 추가하면 새 OAuth 프로바이더가 자동 동작한다.

OAUTH_CONFIGS = { github: { authorization_url: 'https://github.com/login/oauth/authorize', client_id_env: 'GITHUB_OAUTH_CLIENT_ID', scopes: ['repo', 'read:org', 'read:user', 'workflow'] }, // vercel, notion, slack 등 추가 가능 (구조 동일) }

인증 흐름

사용자 → GET /api/oauth/{provider}/authorize → State 토큰 DB 저장 (CSRF 방지) → 외부 OAuth 리다이렉트 외부 → GET /api/oauth/{provider}/callback → Authorization Code → Access Token 교환 → AES-256-GCM 암호화 → service_accounts 테이블 저장 → 앱 리다이렉트

서비스 계정 타입 체계

타입설명예시
oauthOAuth 인증 기반 연동GitHub OAuth
api_keyAPI 키 직접 입력Stripe Secret Key, OpenAI Key
manual수동 입력/설정커스텀 서비스 연결

보안 계층: RLS(Row Level Security) + API 핸들러 소유권 검증 이중 방어, encrypted_access_token/encrypted_refresh_token 암호화 저장, 복호화된 값 로깅/API 응답 포함 금지

2.2 헬스체크 어댑터 현황

src/lib/health-check/에 어댑터 패턴으로 구현. 파일 1개 + registry 등록 1줄로 새 어댑터 추가 가능.

확장 용이성: 기존 stripe 어댑터 패턴을 복제하면 (fetch + AbortSignal.timeout(10s) + 상태 분기) 1-2시간 내 새 어댑터 추가 가능. 등록은 registry.ts에 1줄.

2.5 인프라 제약 (Cloudflare Workers)

항목현재 설정제약 영향

메모리128MB (기본값)대형 응답 파싱 시 주의
번들 크기~1MB compressed외부 SDK 직접 import 금지 → fetch API 직접 사용
상태 유지StatelessWebSocket 제한, 파일시스템 쓰기 불가
캐싱KV Namespace (ISR)카탈로그/상태 정보는 KV 캐시 활용 가능
Rate LimitCloudflare Rules앱 코드에서 추가 구현 금지

Workers 환경에서 외부 API 호출 시 주의사항

  • 외부 SDK 금지: Vercel SDK, Stripe SDK 등을 직접 import하면 번들이 비대해짐 → fetch() API로 직접 호출
  • 타임아웃 필수: 모든 외부 호출에 AbortSignal.timeout(10000) 적용
  • 토큰 갱신: OAuth 토큰 만료 시 자동 refresh 로직 필요 (Workers는 stateless이므로 매 요청마다 체크)
  • Long-running 작업 불가: Webhook 수신 → 즉시 200 → DB 저장 → 클라이언트 폴링 패턴 사용

3. 확장 전략 (To-Be)

3.1 API 직접 연동 전략

A. OAuth 프로바이더 확장 우선순위

바이브코더 관점에서 "연결하면 바로 가치를 체감"할 수 있는 순서:

#프로바이더연동 가치구현 난이도Workers 호환비고
1Vercel 매우 높음 낮음 문제없음 배포 상태 조회, 환경변수 동기화, 프로젝트 관리
2Notion 높음 중간 문제없음 프로젝트 문서 연동, 데이터베이스 동기화
3Slack 중간 중간 Webhook만 배포/헬스체크 알림, 팀 커뮤니케이션
4Discord 중간 중간 Webhook만 커뮤니티/팀 봇 연동
5Google Cloud 중간 높음 토큰 갱신 주의 GCP 서비스 관리, Firebase 연동

구현 방법: OAUTH_CONFIGS 객체에 { authorization_url, client_id_env, scopes } 추가. callback 라우트는 이미 [provider] 동적 라우트로 범용 처리되므로 설정 추가 + 환경변수 등록만으로 동작.

B. API Key 연동 범용화

기존 ServiceConnectionConfig.api_key_fields 구조를 활용하여 UI에서 동적 폼을 생성:

  • Vercel: Deploy Token → 프로젝트/배포 상태 조회
  • Resend/SendGrid: API Key → 이메일 발송 상태 확인
  • PostHog: Project API Key → 분석 이벤트 연동
  • Sentry: Auth Token → 에러 모니터링 (헬스체크 어댑터 이미 존재)

C. Cloudflare Workers 하 외부 API 호출 4대 패턴

패턴설명적용 사례
단발 호출 요청-응답 1회, AbortSignal.timeout(10s) 헬스체크, OAuth 토큰 교환, API Key 검증
병렬 Batch Promise.allSettled()로 다수 서비스 동시 호출 프로젝트 전체 헬스체크, 다중 서비스 상태 조회
ISR 캐싱 KV 캐시에 결과 저장, revalidate 주기 설정 카탈로그 정보, 서비스 상태 대시보드, 공개 API 상태
Webhook Pull Webhook 수신 → 즉시 200 → DB 저장 → 클라이언트 폴링 Stripe 이벤트, GitHub 이벤트, 배포 완료 알림

7. 전략적 권고사항

7.1 지금 vs 나중 — 핵심 판단

지금 해야 할 것

  • 헬스체크 어댑터 확장 — 기존 패턴 복제, 1-2시간/어댑터, 즉시 가치 체감
  • MCP npm 첫 배포 — 기존 3개 tool 안정화 + 배포로 생태계 진입
  • Vercel OAuth — OAUTH_CONFIGS 1개 추가, 바이브코더 배포 경험 직결
  • API Key UI 범용화 — 기존 타입 활용, 연동 서비스 확대의 기반

근거: 모두 기존 인프라 재활용으로 구현 비용 최소, ROI 최대. 지금 안 하면 카탈로그만 많고 실제 연동 3개인 상태가 지속.

고도화 후 해야 할 것

  • 패키지 레지스트리 — DB 설계 필요, Phase 1 완료 후 착수해야 안정적
  • MCP Resources/Prompts — 기존 tool 안정화 선행 필수
  • CLI 확장 — MCP 우선, CLI는 고급 사용자/CI용으로 점진적 확장
  • 커뮤니티 패키지 — 공식 패키지로 검증 후 개방

근거: 기반 없이 구축하면 스키마 변경, 기능 중복, 유지보수 부담. Phase 1에서 패턴을 확립한 후 확장.

7.2 전략적 포지셔닝

Linkmap의 연동 전략은 "npm for Infrastructure"

npm이 코드 패키지의 생태계를 만들었듯, Linkmap은 서비스 인프라 패키지의 생태계를 지향한다.

경쟁사 비교: ┌──────────────┬──────────────────────────────────────────────┐ │ Doppler │ 환경변수 관리만 특화, 서비스 연동/맵 없음 │ │ Vercel │ 배포 + 환경변수, 다른 서비스 연동은 제한적 │ │ Railway │ 자체 인프라 중심, 외부 서비스 통합 약함 │ │ Linkmap │ 서비스 맵 + 환경변수 + 헬스체크 + MCP + 패키지 │ │ │ = 서비스 인프라 통합 관리의 유일한 선택지 │ └──────────────┴──────────────────────────────────────────────┘

차별화 핵심: MCP = AI-first DX

2026년 기준, 대부분의 개발자 도구는 아직 MCP를 본격 지원하지 않는다. Linkmap이 MCP 생태계에 먼저 진입하면:

  • Claude Code / Cursor 사용자가 자연어로 "Supabase 추가해줘"만 하면 끝
  • 바이브코더에게 CLI보다 자연어가 훨씬 낮은 진입장벽
  • 선점 효과: MCP 도구 검색에서 "서비스 관리" 카테고리 1위

7.4 장기 비전

"Claude/Cursor에서 말하면 Linkmap이 서비스를 연결해준다"

MCP가 바이브코더의 AI-first 개발 경험의 핵심 채널이 된다. 패키지 레지스트리는 npm의 서비스 인프라 버전으로, 개발자가 코드 패키지처럼 서비스 인프라를 검색하고 설치하는 세계. 이것이 Linkmap의 장기 moat이다.
