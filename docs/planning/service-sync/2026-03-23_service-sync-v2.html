0. 한눈에 이해하기 — 이 기능이 뭔가요?

쉬운 비유

📦택배 서비스에 비유하면...

여러분이 여러 온라인 쇼핑몰(Vercel, Railway, Netlify)에서 물건을 팔고 있다고 상상해보세요. 각 쇼핑몰마다 배송 정보(API 키, 환경변수)를 따로 입력해야 합니다.
배송 주소가 바뀌면? 모든 쇼핑몰에 하나하나 들어가서 변경해야 합니다.

✨Linkmap Service-Sync는 이걸 해결합니다:
Linkmap에서 한 번만 수정하면, 연결된 모든 플랫폼에 자동으로 전달됩니다.

Linkmap에서 환경변수를 수정하면, 연결된 Vercel/Railway/Netlify에 자동으로 Push됩니다

1. 왜 Push 방식인가? (Pull vs Push 비교)

쉬운 비유

📬Pull = 매번 우체국에 가서 편지를 가져오는 것 (앱이 시작할 때마다 Linkmap에 요청)

🚚Push = 택배 기사가 집까지 배달해주는 것 (Linkmap이 각 플랫폼에 직접 전달)

기각 (2.0/5.0)

Pull 방식 (중계 API)

채택 (3.3/5.0)

Push 방식 (자동 동기화)

3. 기술 아키텍처 — 내부에서 어떻게 작동하나요?

쉬운 비유

🏭공장 컨베이어 벨트에 비유하면: 환경변수가 변경되면 → 컨베이어 벨트(triggerAllSync)가 작동 → 각 플랫폼별 포장 라인(어댑터)에서 해당 플랫폼 형식으로 포장 → 배송(API 호출)

어댑터 패턴: 새로운 플랫폼을 추가하려면 어댑터 파일 하나만 만들면 됩니다

파일 구조 (어댑터 패턴)

src/lib/sync/                          ← 새로 만들 디렉토리
  ├── types.ts                         ← SyncAdapter 인터페이스 정의
  ├── trigger.ts                       ← triggerAllSync() — 핵심 트리거
  ├── adapter-registry.ts              ← 어댑터 등록/조회
  ├── name-map.ts                      ← 플랫폼별 키 이름 매핑 규칙
  └── adapters/                        ← 플랫폼별 어댑터
      ├── github.ts                    ← 기존 auto-sync.ts에서 이동 (이미 구현!)
      ├── vercel.ts                    ← Vercel REST API (Phase 0/1)
      ├── railway.ts                   ← Railway GraphQL (Phase 2)
      └── netlify.ts                   ← Netlify REST API (Phase 2)

기존 코드 (70% 재활용):
  src/lib/github/auto-sync.ts          ← 179줄, 완전 구현됨
  src/lib/github/nacl-encrypt.ts       ← GitHub 전용 암호화
  src/lib/crypto/index.ts              ← AES-256-GCM (공통 사용)
  src/app/api/env/route.ts             ← 환경변수 CUD 트리거 (3곳)

4. 보안 — 어떻게 안전한가요?

쉬운 비유

🏦은행 금고에 비유하면: API 키는 금고(AES-256-GCM)에 암호화되어 저장됩니다. 동기화할 때만 잠깐 꺼내서 → HTTPS 보안 통로로 전달 → 전달 후 각 플랫폼의 자체 금고에 보관됩니다.

암호화 저장 → HTTPS 전송 → 플랫폼 자체 관리 + 모든 동기화 활동은 감사 로그에 기록

CREATE TABLE project_sync_targets (
  id UUID PK,
  project_id FK -> projects(id),
  user_id FK -> auth.users(id),
  platform TEXT CHECK (IN ('github','vercel','railway','netlify')),
  service_account_id FK -> service_accounts(id),
  external_project_id TEXT NOT NULL,
  external_project_name TEXT,
  auto_sync_enabled BOOLEAN DEFAULT false,
  sync_environment TEXT DEFAULT 'production',
  target_environment TEXT,
  last_synced_at TIMESTAMPTZ,
  last_sync_status TEXT,
  last_sync_error TEXT,
  UNIQUE(project_id, platform, external_project_id, sync_environment)
);
