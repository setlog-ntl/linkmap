창작자가 직접 겪은 여정. 이 실화가 글의 뼈대입니다.

📚

PHASE 1 — 결핍

책은 많이 읽었지만, 기억에 남지 않았다

책에 메모, 노션에 메모, 노트에 메모, 사진도 찍었다. 그런데 다시 찾으려면 어디에 있는지 알 수 없었다. 책을 다시 꺼내 찾는 것도 번거로웠다.

📝

PHASE 2 — 노션에서 시작

필요한 기능을 노션에서 직접 만들어 쓰다가

독서 기록 데이터베이스, 템플릿, 관계형 연결... 하지만 한계가 있었다. "이걸 제대로 된 앱으로 만들 수 없을까?"

🔥

PHASE 3 — 첫 도전과 실패

Cursor + Firebase로 1차 MVP — 수많은 실패

직접 만들기 시작했다. Cursor와 Firebase로 1차 MVP가 나왔다. 하지만 그 과정은 실패의 연속이었다.

🤝

PHASE 4 — 전환점

트레바리 독서모임 개발자 → Vercel + Supabase로 처음부터 다시

독서모임에서 만난 개발자의 도움으로 기술 스택을 바꾸고 처음부터 새로 만들기 시작했다.

🚀

PHASE 5 — 도약

Claude를 만나 개발 가속 + 아마존 개발자 조언으로 PRD 우선 접근

Claude와 함께 개발에 박차. 아마존 개발자의 조언으로 PRD를 먼저 만들고 전체 구조를 세팅한 뒤 진행하니, 몇 달 걸리던 것을 일주일 만에 더 좋게 만들어갔다.

🌳

PHASE 6 — 현재 진행형

계속해서 기능 고도화 중 — 851커밋, 310컴포넌트, 99마이그레이션

필사모임 기록, 책 간 연결, AI 리포트... 진짜 책을 읽는 사람이 필요한 기능을 계속 붙여나가는 중.

서사의 핵심 — "내가 쓰기 위해 만드는 서비스"

왜 강점인가

  • • 내가 매일 쓰는 서비스이기에 사용자가 적어도 계속 업데이트
  • • 진짜 독서인의 불편함에서 출발한 기능들
  • • 필사모임에서 매일 한 필사를 기록하고 싶은 실제 니즈
  • • 책을 읽다 떠오르는 다른 책 → "연결된 책" 기능의 탄생

글에 녹일 실제 디테일

  • • 책에 메모 + 노션 + 노트 + 사진 → "흩어진 기록의 고통"
  • • 노션의 한계를 느끼고 직접 코딩 시작한 계기
  • • Firebase → Supabase 전환의 결단
  • • PRD 먼저 → "몇 달 → 일주일"의 극적 대비

2 5막 서사 상세 — 실화 기반 구성

각 막의 Before(기존 글)와 After(실화 기반 고도화)를 비교합니다.

1막: 흩어진 기록 — "어디에 적었더라?"

실화 반영

Before (기존)

"홈페이지가 필요했다."

"나는 개발자가 아니다. 경영학 전공..."

"만드는 건 만드는 사람이 하는 거지."

After — 실화 기반

장면 1: 흩어진 메모들

"책은 많이 읽었다. 한 달에 네다섯 권. 문제는 기억이었다. 좋은 문장을 만나면 밑줄을 쳤다. 책에도 메모를 하고, 노션에도 적고, 종이 노트에도 옮기고, 폰으로 사진도 찍었다. 기록은 성실했다. 그런데 한 달 후, 그 문장을 다시 찾으려면 — 어디에 적었는지 알 수가 없었다."

장면 2: 필사모임

"필사모임에서 매일 필사를 했다. 좋은 문장을 한 글자씩 따라 쓰면서 내 생각도 함께 기록하고 싶었다. 하지만 필사한 것들이 쌓일수록 그것들을 다시 찾아보는 건 더 어려워졌다. 책에 끼워둔 포스트잇은 떨어지고, 노트의 어느 페이지였는지 까먹고, 폰 사진은 수백 장 사이에 묻혔다."

장면 3: 연결의 갈망

"책을 읽다 보면 다른 책이 떠오른다. '이 이야기는 저번에 읽은 책과 통하는데...' 그 연결을 어딘가에 남기고 싶었다. 책과 책 사이의 관계를 눈에 보이게. 하지만 노션의 데이터베이스로는 한계가 있었다."

세계관 선언 (콜백 1회차)

"내가 원하는 건 명확했다. 기록하고, 다시 찾고, 연결하고, 공유할 수 있는 독서 기록 앱. 그런 앱을 만들면 되지 않나? *만드는 건 만드는 사람이 하는 거지.* 그때의 나는 그렇게 생각했다."

실화 디테일: 책+노션+노트+사진에 흩어진 기록, 필사모임의 매일 필사, 책 읽다 떠오르는 다른 책 — 모두 실제 경험에서 온 구체적 결핍.

2막: 시도와 실패 — "노션에서 시작해 Firebase에서 좌절하다"

실화 반영

Before (기존)

1차: Python 강의 → for 루프에서 포기

2차: Bubble 노코드 → 커스텀 플러그인 필요

3차: 외주 견적 300만원

문제: 가상의 시도들. 실화가 훨씬 풍부하고 구체적.

After — 실화 기반

1차 — 노션에서 직접 만들어 쓰기 (한계 인식)

"포기하는 대신 노션을 선택했다. 데이터베이스를 만들고, 독서 템플릿을 설계하고, 관계형 속성으로 책과 메모를 연결했다. 꽤 잘 동작했다. 한동안은. 그런데 기록이 100개를 넘어가자 느려졌다. OCR은 당연히 안 됐다. 사진을 찍어서 문장을 자동으로 텍스트로 바꿔주는 기능, 독서모임 친구들과 기록을 공유하는 기능 — 내가 정말 원하는 것들은 노션의 범위 밖이었다."

*도구의 한계. 노션은 좋은 도구지만, 내가 만들고 싶은 건 '앱'이었다.*

2차 — Cursor + Firebase로 1차 MVP (실패의 연속)

"그래서 직접 만들기로 했다. Cursor를 깔고, Firebase를 연결하고, AI에게 시켰다. '독서 기록 앱 만들어줘.' 뭔가가 만들어졌다. 동작도 했다. 1차 MVP. 하지만 기쁨은 짧았다. 기능을 하나 추가하면 다른 곳이 깨졌다. 에러를 고치면 새 에러가 났다. Firebase의 구조가 점점 복잡해지면서 내가 뭘 만들고 있는지도 모르겠는 상태가 됐다."

"몇 달을 그렇게 보냈다. 만들고, 부수고, 다시 만들고. 진전은 있었지만 확신은 없었다."

*수많은 실패. 하지만 이 과정에서 내가 원하는 앱의 모습은 점점 선명해졌다.*

체념의 순간

"어느 날 밤, 또 에러 앞에 앉아 있었다. 몇 시간째 같은 곳에서 막혀 있었다. *나는 읽는 사람이지, 만드는 사람이 아닌가 봐.* 그때 정말 그렇게 느꼈다."

실화 디테일: 노션 → Firebase 1차 MVP의 실제 여정. "만들고, 부수고, 다시 만들고"의 반복. 기존 글의 가상 시도(Python 강의/Bubble/외주)보다 훨씬 진정성 있음.

3막: 전환점들 — "처음부터 다시, 그리고 도약"

실화 반영

Before (기존)

"2025년이 왔다" + "충격, 그리고 의문"

"뉴스에서 AI가 코드를 짜준다는 이야기"

"30분 만에 로그인 페이지"

문제: 실제 여정은 "한 번의 마법 같은 30분"이 아니라, 여러 전환점이 겹친 도약의 과정.

After — 실화 기반

전환점 1: 트레바리 독서모임의 개발자

"전환은 예상하지 못한 곳에서 왔다. 트레바리 독서모임. 거기서 개발자를 만났다. 내 앱 이야기를 했더니 코드를 봐줬다. 그리고 한마디. '이거, 처음부터 다시 만드는 게 나을 것 같아요. Firebase 대신 Supabase 써보세요.'"

"처음부터 다시. 몇 달을 붙잡고 있던 코드를 놓는다는 뜻이었다. 두려웠지만, 이대로는 더 안 된다는 것도 알고 있었다. Vercel과 Supabase로, 처음부터 다시 시작했다."

전환점 2: Claude를 만나다

"새로 시작하면서 Claude를 만났다. Cursor만 쓰던 때와 달랐다. Claude는 코드만 짜주는 게 아니라, 내가 뭘 만들고 싶은지를 이해하려고 했다. '이 기능은 이렇게 구현하면 나중에 확장할 때 문제가 될 수 있어요'라고 말해주는 느낌. 개발에 박차가 붙었다."

전환점 3: 아마존 개발자의 한마디 (CLIMAX)

"결정적이었던 건 아마존 개발자의 조언이었다. 'PRD를 먼저 만들어. 뭘 만들지 정리하고, 전체 구조를 세팅한 다음에 코드를 짜.' 그때까지 나는 떠오르는 대로 기능을 붙이고 있었다. 머릿속의 그림을 문서로 정리했다. 전체 구조를 먼저 세팅했다."

"그러자 마법이 일어났다. 몇 달 동안 삽질하며 만들던 것을, 일주일 만에 더 좋게 만들어냈다."

"일주일. 진짜 일주일이었다. *이게 되는 거야?* 같은 나인데, 같은 AI를 쓰고 있는데. 달라진 건 하나 — 내가 뭘 만들지 정확히 알고, 그걸 먼저 정리한 것."

실화 디테일: 3개의 전환점이 겹치며 도약. 트레바리 개발자(기술 스택 전환) → Claude(개발 가속) → 아마존 개발자(PRD 우선 접근). "몇 달 → 일주일"이 클라이맥스.

4막: 깨달음 — "불만이 곧 기획서였다"

실화 반영

Before (기존)

인쇄기-악기-카메라 비유 (추상적)

"도구가 바뀐 것이다" (건조)

After — 실화 기반

콜백 2회차 — 뒤집힘

"*만드는 건 만드는 사람이 하는 거지.* 틀렸다. '만드는 사람'의 정의가 바뀌었다. 코드를 작성할 수 있는 사람이 만드는 사람이 아니라, 무엇을 만들지 알고 있는 사람이 만드는 사람이다."

실화의 무게 — "5년간의 불만"

"돌이켜보면, 나는 5년 동안 PRD를 쓰고 있었던 거다. 사진 찍으면 텍스트로 바뀌어야 한다(OCR). 필사하면서 내 생각을 함께 남길 수 있어야 한다. 책을 읽다 다른 책이 떠오르면 연결할 수 있어야 한다. 독서모임 친구들과 기록을 나눌 수 있어야 한다."

"5년간의 불만이, 사실은 가장 정확한 기획서였다."

인쇄기-악기-카메라 비유 유지

"도구가 바뀌면, 만드는 사람도 바뀐다. 아이디어가 있다면, 필요를 느끼고 있다면 — 당신은 이미 만들 수 있는 사람이다."

핵심 문장: "5년간의 불만이 가장 정확한 기획서였다" — 이 한 줄이 글 전체의 테마를 압축. OCR, 필사 기록, 책 간 연결, 모임 공유 등 실제 기능이 열거되며 설득력 극대화.

5막: 현재와 여운 — "사용자가 적어도 상관없다"

실화 반영

Before (기존)

5개 불릿 리스트 (배포, 도메인, DB, API 키, OAuth)

WARNING 콜아웃 + 다음 편 예고

After — 실화 기반

현실의 벽 (에피소드)

"앱은 만들어졌지만, 세상에 내놓는 건 또 다른 이야기였다. 배포, 환경변수, API 키 관리, 서비스 연결 — AI가 코드를 짜줬지만, 이 연결들은 직접 해야 했다. 그리고 그 연결의 세계가 코딩만큼이나 넓다는 걸 알게 됐다."

서사의 핵심 — 내가 쓰기 위한 서비스

"하지만 한 가지, 이 서비스가 다른 점이 있다. 이건 내가 매일 쓰는 앱이다. 매일 책을 읽고, 매일 기록하고, 매일 쓴다. 사용자가 많지 않아도 상관없다. 내가 사용자니까. 그래서 계속 업데이트하고, 계속 개선한다. *진짜 책을 읽는 사람이, 진짜 자기가 쓰려고 만든 서비스* — 이게 이 앱의 가장 큰 강점이라고 생각한다."

콜백 3회차 + 여운

"나는 더 이상 '만드는 건 만드는 사람이 하는 거지'라고 말하는 사람이 아니다. 나는 읽는 사람이자, 만드는 사람이 됐다. 아직 부족한 게 많지만, 필사 기록 기능을 붙이고, 책과 책을 연결하는 기능을 추가하고, 독서모임 친구들이 쓸 수 있게 다듬고 있다. 851번째 커밋을 찍으면서 드는 생각."

"읽는 사람이 만드는 사람이 되는 시대. 이건 시작일 뿐이다."

실화 디테일: "사용자가 적어도 상관없다. 내가 사용자니까" — 이 진정성이 글 전체의 설득력. 851커밋으로 현재진행형 강조. "읽는 사람이자 만드는 사람"으로 정체성 전환 완결.
