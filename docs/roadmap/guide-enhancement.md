## 1. 현황 분석

### 1.1 가이드 시스템 구조

```
가이드
├── 공개 가이드 (정적 컴포넌트, /guides/)
│   ├── 기본 개념 (5종)
│   │   ├── env      — 환경변수 완전 정복 (10분)
│   │   ├── auth     — 인증 가이드 (8분)
│   │   ├── frontend — 프론트엔드 가이드 (12분)
│   │   ├── backend  — 백엔드 가이드 (10분)
│   │   └── deploy   — 도메인·배포·서버 (15분)
│   └── 서비스 가이드 (3종, 상세 단계별)
│       ├── github     — GitHub 시작하기 (30분)
│       ├── cloudflare — Cloudflare 연결 (40분)
│       └── openai     — OpenAI 연동 (15분)
│
├── DB 기반 서비스 가이드 (service_guides 테이블, 180+ 서비스)
│   ├── seed 파일: src/data/seed/service-guides*.ts (6 배치)
│   └── 구조: quick_start / setup_steps / code_examples /
│             common_pitfalls / integration_tips / pros / cons
│
└── AI QnA (ai_feature_qna 테이블)
    └── answer_guide 필드 포함
```

### 1.2 가이드 허브 현황

- **파일**: `src/data/ui/guide-meta.ts`
- **하드코딩**: 8개 고정 (`GUIDE_LIST` 배열)
- **카테고리**: `concept` / `service` 2종
- **표시 정보**: 제목, 설명, 아이콘, 뱃지, 읽기 시간

| 필드 | 설명 | UI 활용 현황 |
|------|------|-------------|
| `quick_start` | 빠른 시작 한글 | ✅ 활용 중 |
| `quick_start_en` | 빠른 시작 영문 | ✅ 활용 중 |

### 현황 분석에서 도출된 기능

#### F-001 — 가이드 검색
- **출처**: 현황분석 TD-5
- **문제**: 180+ 서비스 가이드를 탐색할 방법이 없음
- **해결**: 가이드 허브 상단에 실시간 검색창 추가 (서비스명 + 설명 대상)
- **검토**: 클라이언트 사이드 필터 vs Supabase FTS

#### F-002 — common_pitfalls UI 표시
- **출처**: 현황분석 TD-3
- **문제**: DB에 `common_pitfalls` 데이터가 있으나 서비스 가이드 상세 페이지에 표시되지 않음
- **해결**: 서비스 가이드 상세 내 "흔한 실수" 섹션 추가
- **검토**: `SetupStep` 이후 배치, 아코디언 UI 고려

#### F-003 — integration_tips UI 표시
- **출처**: 현황분석 TD-3
- **문제**: DB에 `integration_tips` 데이터(서비스 간 연동 팁)가 있으나 미사용
- **해결**: "함께 쓰면 좋은 서비스" 섹션 + 연결 서비스 카드 링크
- **검토**: `with_service_slug`로 서비스 메타 조회 필요

#### F-004 — 가이드 허브 동적 확장
- **출처**: 현황분석 TD-2
- **문제**: `GUIDE_LIST` 하드코딩으로 가이드 추가/제거가 코드 변경을 요구함
- **해결**: DB 기반 또는 설정 파일 기반으로 전환
- **검토**: 현재 정적 빌드에 최적화되어 있어 SSG 호환 방안 필요

#### F-006 — 서비스 소개 (Overview) 페이지 구조 추가
- **출처**: FB-001
- **문제**: 사용자가 서비스 가이드 진입 시 "이 서비스가 뭔지" 파악할 방법이 없음. `quick_start`가 코드 설치부터 시작해 초보자에게 낯설음
- **해결**: 가이드 최상단에 Overview 섹션 추가 — 서비스 한 줄 요약 + 제공 기능 분류 카드 + 가입 방법 개괄
- **신규 데이터 필드**: `overview_detail` (TEXT), `signup` (JSONB), `features` (JSONB)

#### F-007 — 기능 분류(Feature) 단위 가이드
- **출처**: FB-001
- **문제**: 서비스가 복수의 기능을 제공할 때(예: Stripe → 결제·구독·Connect·Radar) 단일 setup_steps로는 표현 불가. 기능마다 필요한 API 키도 다를 수 있음
- **해결**: `features[]` 배열 도입 — 각 Feature는 id/name/description/tag(free|paid|beta)를 가지며 독립적인 api_key 발급 단계와 setup_steps를 포함
- **검토**: 기존 `setup_steps` 데이터는 features[0](기본 기능)으로 마이그레이션

#### F-008 — 기능별 API 키 발급 단계 (초보자용)
- **출처**: FB-001
- **문제**: 현재 `api_key_url`은 URL 링크만 제공 — "어디서 복사하는지" 단계별 안내 없음
- **해결**: `api_key.issue_steps[]` — 스크린샷 힌트 포함 단계별 발급 안내. 예: "① 왼쪽 메뉴에서 API Keys 클릭 → ② Create new secret key → ③ 복사 후 .env에 저장"
- **검토**: image_hint는 실제 스크린샷 대신 UI 경로 텍스트로 먼저 구현

#### F-009 — 가입 안내 (Signup) 섹션
- **출처**: FB-001
- **문제**: 현재 가이드는 이미 계정이 있다는 전제로 시작 — "처음 가입하는" 초보자용 흐름 없음
- **해결**: `signup` 객체 — 가입 URL + 가입 단계(3~5개 텍스트) + 무료 플랜 설명
- **검토**: 가이드 상단 "시작하기" 탭 또는 별도 섹션으로 배치

#### F-005 — 가이드 → 프로젝트 바인딩 연결
- **출처**: 현황분석 TD-4
- **문제**: 가이드를 읽은 후 실제 프로젝트 설정으로 이동하는 흐름이 없음
- **해결**: 가이드 하단에 "이 서비스를 내 프로젝트에 추가" CTA 버튼
- **검토**: 로그인 상태 체크, 프로젝트 선택 모달 또는 `/project/[id]` 라우팅
