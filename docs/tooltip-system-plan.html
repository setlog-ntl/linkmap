📋 Context

Linkmap의 서비스맵, 대시보드, 환경변수 테이블 등에서 아이콘 전용 버튼(Copy, Eye, Edit 등)과 서비스 아이콘(ServiceIcon)이 설명 없이 사용되고 있어, 사용자가 기능을 직관적으로 이해하기 어려운 상황입니다.

현재 11개 파일에서 Tooltip을 사용 중이나 일관성 없이 적용되어 있고, 전역 delayDuration=0은 업계 안티패턴으로 진단되었습니다.

벤치마킹 결과 (Vercel, Linear, Figma, Notion, GitHub): 업계 표준은 300ms이며, Radix skipDelayDuration을 활용한 연속 탐색 최적화가 서비스맵에 최적.

⚙️ 설계 원칙

1

3-Tier 계층 구조

정보 밀도별 구분 — Simple Label / Service Label / Rich Info

2

의도적 트리거

delay 300ms 기본, skip delay 200ms로 연속 탐색 지원

3

데이터 중앙 관리

DB description_ko + 정적 상수로 이중 관리

4

컴포지션 패턴

ServiceIcon은 순수 렌더링 유지, 외부 래퍼로 Tooltip 결합

5

접근성 준수

aria-label + role="tooltip" + 키보드 포커스 지원

📊 Tier 정의

Tier 대상 정보 Delay 예시
Tier 1 아이콘 전용 버튼 1줄 행동 동사 400ms (전역) "복사", "편집", "값 표시"
Tier 2 ServiceIcon (목록/카드) 이름 + 카테고리 300ms "Supabase — 데이터베이스"
Tier 3 서비스맵 노드, 경고 배지 이름/상태/카테고리/env 진행률 300ms 기존 NodeTooltip 패턴

🚀 구현 계획

P1

Phase 1: 기반 정비 (전역 설정 + 래퍼 컴포넌트)

1-1. 전역 TooltipProvider 설정 변경

src/components/providers.tsx
  • delayDuration={0} → delayDuration={400}
  • skipDelayDuration={200} 추가
업계 표준 적용 + 서비스맵 연속 탐색 최적화

1-2. tooltip.tsx sideOffset 기본값 변경

src/components/ui/tooltip.tsx
  • sideOffset 기본값 0 → 4
트리거 요소를 가리지 않도록 간격 확보 (NNGroup 권장)

1-3. IconTooltip 래퍼 컴포넌트 생성 Tier 1

src/components/ui/icon-tooltip.tsx (신규)
interface IconTooltipProps {
  label: string;
  shortcut?: string;        // 단축키 (예: "Ctrl+C")
  side?: 'top' | 'bottom' | 'left' | 'right';
  children: React.ReactNode;
}

1-4. ServiceTooltip 래퍼 컴포넌트 생성 Tier 2

src/components/ui/service-tooltip.tsx (신규)
interface ServiceTooltipProps {
  serviceId: string;
  serviceName: string;
  category?: string;
  description?: string;
  side?: 'top' | 'bottom' | 'left' | 'right';
  children: React.ReactNode;
}

1-5. 중복 TooltipProvider 제거

src/components/env/env-data-table.tsx src/components/env/env-filter-bar.tsx
전역 Provider가 이미 존재하므로 로컬 <TooltipProvider> 래핑 제거
P2

Phase 2: Tier 1 — 아이콘 버튼 전수 적용

P0 핵심 핵심 동작 버튼

  • env-data-table.tsx — Copy("복사"), Eye/EyeOff("값 표시"/"숨기기"), Pencil("수정"), MoreHorizontal("더보기")
  • map-toolbar.tsx — 기존 title → IconTooltip 전환 ("전체 보기", "PNG 다운로드", "자동 정렬", "범례")
  • node-edit-toolbar.tsx — "연결 시작", "상세 보기", "서비스 제거"

P1 레이아웃 / 네비게이션

  • header.tsx — 테마 토글, 사용자 메뉴
  • app-header.tsx — 모바일 메뉴

  • layer-card.tsx — 레이어 아이콘 (Monitor/Server/Wrench)
P3

Phase 3: Tier 2 — 서비스 아이콘 툴팁

3-1. 서비스 설명 상수 생성

src/lib/constants/service-descriptions.ts (신규)
  • 형태: Record<string, string> — slug별 50자 이내 한 줄 설명
  • 소스: seed 데이터 services.ts의 description_ko 축약
  • 헬퍼: getServiceDescription(slug: string): string | undefined

3-2. ServiceTooltip 적용 대상

  • dashboard/service-item.tsx — 대시보드 서비스 카드
  • dashboard/connection-flow-map.tsx — FlowPill 내 서비스 아이콘
  • service/add-service-dialog.tsx — 서비스 선택 다이얼로그
  • service/service-list-item.tsx — 서비스 목록
P4

Phase 4: Tier 3 — NodeTooltip 고도화

4-1. description 필드 추가

  • service-map/node-tooltip.tsx — description prop 추가, 이름 아래에 1줄 설명 표시
  • service-map/service-node.tsx — ServiceNodeData에 description 추가
  • 데이터 소스: DB의 services.description_ko (useServiceMapNodes 훅에서 이미 접근 가능)
P5

Phase 5: 모바일 대응

모바일 최적화 전략

  • 기존 src/hooks/use-mobile.ts 활용
  • 아이콘 버튼: 모바일에서 가능한 경우 텍스트 라벨 병행 (hidden sm:inline 패턴 확대)
  • 서비스맵 노드: 모바일 탭 시 하단 Sheet로 상세 정보 (기존 Sheet 컴포넌트 활용)
  • Radix Tooltip은 터치에서 long-press로 동작 (기본 지원)

✅ 검증 방법

  • 1
    타입 체크: npm run typecheck — 모든 인터페이스 변경 반영 확인
  • 2
    빌드: npm run build — 빌드 성공 확인
  • 3
    로컬 확인 (npm run dev):
    • 서비스맵 노드 호버 → NodeTooltip에 description 표시
    • 아이콘 버튼(Copy, Eye 등) 호버 → 400ms 후 Simple Label 표시
    • 연속 호버 시 skipDelay(200ms) 동작 확인 (두 번째부터 즉시 표시)
    • 대시보드 서비스 아이콘 호버 → 서비스명 + 카테고리 표시
    • 모바일 뷰포트(375px)에서 long-press 동작 확인
  • 4
    접근성: 키보드 Tab으로 아이콘 버튼 포커스 시 Tooltip 표시 확인
  • 5
    기존 테스트: npm run test — 기존 테스트 깨지지 않는지 확인
