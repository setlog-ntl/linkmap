3. 서비스별 상세 기획

탭을 클릭하여 각 서비스의 상세 기획을 확인하세요

📋 문제 정의

현재 Linkmap의 환경변수 시스템은 현재 값만 저장합니다. 변경 이력이 보존되지 않아 다음 문제가 발생합니다:

  • "어제까지 잘 되던 API가 왜 안 되지?" → 어떤 값이 바뀌었는지 확인 불가
  • Production 장애 시 이전 정상 상태로 즉시 복원 불가
  • staging vs production 환경 간 어떤 키가 다른지 비교 불가
  • 팀원이 실수로 값을 덮어써도 원본 복구 불가

⚡ 핵심 기능

  • 모든 env_var 변경 시 이전 값을 암호화된 스냅샷으로 자동 보존
  • 변경자 ID, 변경 시각, 변경 사유(optional) 기록
  • 스냅샷 값도 AES-256-GCM으로 암호화 — 평문 저장 없음
  • 보존 기간: Free 30일 / Pro 90일 / Enterprise 무제한
  • 특정 시점의 환경변수 전체 상태를 한 번에 복원
  • 개별 키 단위 또는 전체 스냅샷 단위 선택 복원
  • 복원 전 영향 범위 미리보기 (어떤 서비스가 영향받는지 서비스맵 하이라이트)
  • 복원 작업도 감사 로그에 기록
  • development / staging / production 환경 간 차이 시각적 비교
  • 키 존재 여부, 값 일치 여부, 마지막 변경 시각 비교
  • "staging에만 있는 키", "prod에서 변경된 키" 등 필터링
  • 디프 결과에서 바로 값 동기화 (원클릭 복사)

🎬 사용 시나리오

시나리오: Production 장애 시 즉시 복원

개발자 A가 프로덕션의 STRIPE_SECRET_KEY를 실수로 테스트 키로 변경함 → 결제 실패 발생 → EnvTimeline에서 30분 전 스냅샷 확인 → 이전 값 원클릭 복원 → 서비스맵에서 Stripe 노드 정상 상태 확인 → 장애 복구 완료 (MTTR: 2분)

시나리오: 환경 간 동기화 검증

배포 전 staging↔production 디프 뷰 실행 → 3개 키 불일치 발견 (DATABASE_URL, REDIS_URL, API_VERSION) → DATABASE_URL은 의도적 차이(확인), API_VERSION은 동기화 누락 → 원클릭 동기화 후 배포 진행

🗄 기술 설계

-- env_snapshots 테이블 CREATE TABLE env_snapshots ( id uuid PRIMARY KEY DEFAULT gen_random_uuid(), env_var_id uuid REFERENCES env_vars(id) ON DELETE CASCADE, project_id uuid REFERENCES projects(id) ON DELETE CASCADE, encrypted_value text NOT NULL, -- AES-256-GCM 암호화된 이전 값 changed_by uuid REFERENCES auth.users(id), change_reason text, environment text CHECK (environment IN ('development','staging','production')), created_at timestamptz DEFAULT now() ); -- RLS 정책 ALTER TABLE env_snapshots ENABLE ROW LEVEL SECURITY; CREATE POLICY "owner_access" ON env_snapshots USING (project_id IN ( SELECT id FROM projects WHERE user_id = auth.uid() )); -- 인덱스 CREATE INDEX idx_snapshots_env_var ON env_snapshots(env_var_id, created_at DESC); CREATE INDEX idx_snapshots_project ON env_snapshots(project_id, created_at DESC);

🔒 보안 고려사항

  • 스냅샷 값은 반드시 AES-256-GCM으로 암호화하여 저장 — 평문 스냅샷 금지
  • 복원 시 감사 로그 필수 기록 (logAudit: env.restore 이벤트)
  • RLS로 프로젝트 소유자만 스냅샷 접근 가능
  • TTL 정리 시에도 암호화 상태 그대로 삭제 — 복호화 후 삭제하지 않음

📋 문제 정의

현재 Linkmap에는 키 만료일 추적이 전혀 없습니다. 실제 발생하는 문제:

  • API 키가 만료되어 서비스 장애 → 만료 시점을 몰라 사전 대응 불가
  • OAuth 토큰 갱신을 수동으로 해야 함 → 갱신 누락 시 서비스 중단
  • 보안 감사에서 "키 로테이션 정책 없음" 지적 → 컴플라이언스 미충족
  • 90일 이상 미갱신 키가 얼마나 있는지 파악 불가

⚡ 핵심 기능

  • 각 env_var에 expires_at 필드 추가 — 수동 설정 또는 서비스별 자동 감지
  • D-7, D-3, D-1 사전 알림 (대시보드 배너 + 이메일)
  • 만료 임박 키를 서비스맵에서 경고 아이콘으로 시각화
  • 만료된 키는 자동으로 서비스 노드에 "위험" 상태 표시
  • OAuth 2.0 refresh_token 기반 자동 갱신 워크플로
  • 지원 서비스: Google, GitHub, Stripe, Slack 등 주요 OAuth 제공자
  • 갱신 실패 시 즉시 알림 + 수동 갱신 가이드 표시
  • 갱신 이력 EnvTimeline과 연동 (자동 스냅샷 생성)
  • 로테이션 정책 설정: 30/60/90일 주기 또는 커스텀
  • 로테이션 체크리스트: 새 키 생성 → 테스트 → 이전 키 비활성화
  • 서비스별 로테이션 가이드 (예: Stripe 키 교체 절차)
  • 로테이션 완료 후 자동 Health Check 실행

🎬 사용 시나리오

시나리오: API 키 만료 사전 예방

KeyRotator가 Sendgrid API 키 만료 D-7 알림 발송 → 개발자가 대시보드에서 경고 확인 → "키 로테이션 시작" 클릭 → Sendgrid 콘솔에서 새 키 생성 → Linkmap에 붙여넣기 → Health Check 자동 실행 → 이메일 발송 테스트 성공 → 이전 키 자동 비활성화

시나리오: OAuth 토큰 자동 갱신

Google OAuth access_token 만료 1시간 전 → KeyRotator가 refresh_token으로 자동 갱신 시도 → 새 access_token 획득 → EnvTimeline에 갱신 스냅샷 자동 기록 → 서비스맵 Google 노드 정상 유지 → 개발자 개입 없이 무중단 운영

🔒 보안 고려사항

  • refresh_token은 별도 암호화 저장 — env_var와 동일한 AES-256-GCM 적용
  • 자동 갱신 시에도 감사 로그 기록 (initiator: "system/auto-rotate")
  • 로테이션 중 이전 키와 새 키가 동시 유효한 "그레이스 피리어드" 지원
  • 갱신 실패 시 이전 키 유지 — 자동으로 키를 삭제하지 않음

📋 문제 정의

현재 접근 제어는 프로젝트 소유자 단위의 all-or-nothing입니다. 팀 환경에서의 문제:

  • 주니어 개발자도 프로덕션 DB 비밀번호에 동일한 접근 권한
  • 어떤 팀원이 언제 어떤 환경변수를 조회했는지 추적 불가
  • .env 파일에 노출된 키가 있는지 자동 감지 불가
  • 보안 감사 대응 시 "접근 제어 정책"을 증명할 수 없음

⚡ 핵심 기능

  • 4단계 접근 등급: Public / Internal / Confidential / Restricted
  • 등급별 복호화 권한 차등: Restricted는 Owner만, Confidential은 Admin+
  • 자동 등급 추천: 키 이름 패턴 기반 (예: *_SECRET_* → Restricted)
  • 서비스맵에서 등급별 색상 코딩 시각화
등급복호화수정삭제예시
Public전체Member+Admin+NEXT_PUBLIC_*
InternalMember+Admin+Admin+API_BASE_URL
ConfidentialAdmin+Admin+OwnerDATABASE_URL
RestrictedOwnerOwnerOwner*_SECRET_KEY
  • 이상 패턴 감지: 심야 시간 대량 조회, 새 IP에서 Restricted 접근
  • 접근 빈도 기준선 학습 → 이탈 시 알림
  • 실시간 접근 로그 대시보드 (who, what, when, where)
  • 의심 접근 시 자동 일시 잠금 + Owner 승인 요청

프로젝트의 환경변수 보안 상태를 종합 점수로 산출합니다:

암호화 적용률30점
접근 등급 설정률25점
키 로테이션 준수율20점
만료 키 없음15점
이상 접근 0건10점

🎬 사용 시나리오

시나리오: 보안 감사 대응

외부 보안 감사관이 "환경변수 접근 통제 정책을 증명하라" 요청 → EnvShield 대시보드에서 접근 등급 현황, 접근 로그, 보안 점수(87/100) 즉시 제출 → Restricted 등급 키의 접근 이력 + 이상 탐지 0건 리포트 → 감사 통과

시나리오: 비정상 접근 자동 차단

새로운 IP에서 새벽 3시 Restricted 등급 키 20개 연속 조회 시도 → EnvShield 이상 패턴 탐지 → 해당 세션 자동 일시 잠금 → Owner에게 즉시 알림 (Slack + 이메일) → Owner가 확인 후 "차단 유지" 결정 → 접근 차단 + 감사 로그 기록

🗄 기술 설계

🔒 보안 고려사항

  • 접근 로그는 사용자가 삭제할 수 없음 — 감사 증적 보전
  • ip_address, user_agent 수집 시 개인정보처리방침 업데이트 필요
  • 자동 잠금은 "일시 잠금"만 — 영구 차단은 Owner 수동 결정
  • 보안 점수 로직은 서버사이드 전용 — 클라이언트에 점수 공식 노출 금지

5. 시너지 매트릭스 & 구현 로드맵

3개 서비스 간 연동 시너지와 단계별 구현 계획

서비스 간 시너지

Timeline × Rotator

키 로테이션 시 자동으로 이전 값 스냅샷 생성. 로테이션 실패 시 Timeline에서 즉시 이전 키로 롤백 가능. 로테이션 이력이 Timeline에 통합 표시.

Rotator × Shield

Restricted 등급 키의 로테이션 주기 강제. 보안 점수에 "로테이션 준수율" 반영. 미갱신 Restricted 키 자동 경고.

Shield × Timeline

접근 등급에 따른 스냅샷 조회 권한 차등. 이상 접근 탐지 시 해당 시점 스냅샷 자동 보존. 접근 로그 + 변경 이력 통합 감사 뷰.

구현 로드맵

Phase 1 — Week 1~2
EnvTimeline 핵심 구현
env_snapshots 테이블 + 변경 트리거 + 스냅샷 API + 타임라인 UI. 기존 env_vars CRUD에 스냅샷 생성 로직 삽입. 서비스맵 복원 하이라이트.
Phase 2 — Week 2~4
KeyRotator 핵심 구현
expires_at 필드 + 만료 체크 cron + 알림 시스템 + 로테이션 위저드 UI. OAuth 갱신 로직 (Google, GitHub 우선). Timeline 연동.
Phase 3 — Week 4~6
EnvShield 핵심 구현
access_level 필드 + 접근 로그 테이블 + 보안 점수 계산 + 이상 탐지 로직. 자동 등급 추천 + 서비스맵 등급 오버레이.
Phase 4 — Week 6~7
통합 & 고도화
3개 서비스 간 시너지 연동 구현. 통합 보안 대시보드. 구독 플랜별 기능 차등. E2E 테스트. 문서화.

6. 보안 아키텍처 통합도

5계층 보안 아키텍처 — 신규 3개 서비스가 어떻게 기존 보안 체계에 통합되는지

L1
전송 계층 — Cloudflare + HTTPS
Cloudflare Workers 배포. 모든 통신 TLS 1.3. DDoS 보호 및 Rate Limiting (Cloudflare Rules).
L2
인증 계층 — Supabase Auth + OAuth
Google/GitHub OAuth. JWT 검증. 모든 API에서 getUser() 필수. + KeyRotator: OAuth 토큰 자동 갱신
L3
인가 계층 — RLS + 소유권 검증
Supabase RLS 정책. API에서 user_id 이중 검증. + EnvShield: 4단계 접근 등급 (Public→Restricted)
L4
데이터 계층 — AES-256-GCM 암호화
env_vars.encrypted_value 암호화. 서버사이드 전용 복호화. + EnvTimeline: 스냅샷도 동일 암호화 적용
L5
감사 계층 — Audit Log + 모니터링
logAudit() 필수. + EnvShield: 접근 로그 + 이상 탐지 + 보안 점수. + EnvTimeline: 복원 감사 기록. + KeyRotator: 로테이션 감사 기록.
