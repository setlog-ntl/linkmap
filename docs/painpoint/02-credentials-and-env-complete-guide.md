## 1. 크레덴셜이란?

**크레덴셜(Credential)** = **외부 서비스를 사용할 때, "나(또는 우리 앱)가 권한이 있는 사용자다"라고 증명하는 비밀 정보**입니다.

### 1.1 일상에서 비유하면

- **은행 앱**에 로그인할 때 쓰는 **비밀번호** → 은행 서버에게 "내가 맞다"를 증명하는 **크레덴셜**
- **우리 웹 서비스**가 **Google Vision API**를 쓰려고 할 때 제출하는 **JSON 키 파일** → Google에게 "이 앱이 Vision API 쓸 권한이 있다"를 증명하는 **크레덴셜**

즉, **비밀번호, API 키, JSON 키 파일, 토큰(Token)** 등은 모두 **크레덴셜의 한 종류**라고 보면 됩니다.

### 1.2 왜 "그대로 코드나 설정에 적으면 안 되나?"

- 코드나 공개된 설정 파일에 **키 값을 직접 적어 두면**, Git에 올라가거나 다른 사람이 볼 때 **유출**됩니다.
- 그래서 **실제 값**은 **별도 파일(.env.local)·환경변수·비밀 저장소**에 두고, 코드나 공개 설정에는 **변수 이름(예: `GOOGLE_APPLICATION_CREDENTIALS`)** 또는 **경로**만 적는 방식으로 관리합니다.

## 2. 환경변수란?

**환경변수(Environment Variable)** = **프로그램이 실행되는 그 환경(내 PC, 또는 서버)**에서 "이름 = 값" 형태로 미리 넣어 두는 설정값입니다. 프로그램은 **이름**으로 **값**을 읽어 씁니다.

### 2.1 왜 쓰나?

- **비밀값(API 키, DB 비밀번호 등)**을 코드 안에 직접 쓰지 않기 위해
- **환경마다 다른 값**을 쓰기 위해 (로컬은 로컬 DB, 운영은 운영 DB처럼)
- **한 곳에서 이름만 관리**하고, 값은 로컬/운영 각각 다르게 넣기 위해

### 2.2 예시

- `NEXT_PUBLIC_SUPABASE_URL` = `https://xxxx.supabase.co`
- `SUPABASE_SERVICE_ROLE_KEY` = `eyJhbGci...` (긴 문자열)
- `GOOGLE_APPLICATION_CREDENTIALS` = `C:/Users/본인/secure-keys/key.json` (파일 경로)

프로그램은 예를 들어 `process.env.GOOGLE_APPLICATION_CREDENTIALS`로 이 값을 읽습니다. **값 자체**는 코드에 없고, **실행 환경**에만 있습니다.

## 3. 로컬 vs 운영 — 반드시 구분해야 하는 이유

| 구분 | 의미 | 프로그램이 실제로 돌아가는 곳 |
|------|------|------------------------------|
| **로컬 (개발 환경)** | 내 PC에서 `npm run dev` 등으로 실행할 때 | **내 PC** |
| **운영 (프로덕션)** | 사용자에게 제공하는 실제 서비스 (배포 후) | **Cloudflare, Vercel, AWS 등 클라우드 서버** |

중요한 점: **프로그램이 돌아가는 그 컴퓨터만** 그 환경의 파일·환경변수를 읽을 수 있습니다.

- **로컬**에서 돌리면 → **내 PC**의 `.env.local`·내 PC 디스크의 파일만 접근 가능
- **운영**에서 돌리면 → **배포 플랫폼(Cloudflare/Vercel 등)**에 등록한 환경변수·시크릿만 접근 가능. **내 PC의 C: 드라이브는 보이지 않음**

그래서 **로컬용 설정**과 **운영용 설정**을 **반드시 구분**해서, 각각 **해당 환경이 읽을 수 있는 곳**에 넣어야 합니다.

## 4. 핵심 규칙: 어디서 돌리느냐에 따라 어디에 둔다

아래 한 표가 전체 구조를 담습니다.

| 환경 | 프로그램이 돌아가는 곳 | 크레덴셜·연결 정보를 둘 곳 | 예시 |
|------|------------------------|----------------------------|------|
| **로컬 개발·테스트** | **내 PC** | **`.env.local`** (또는 내 PC의 키 파일 경로를 이 파일에 적기) | API 키, DB URL, Google 키 경로 등을 `.env.local`에 작성. Git에는 올리지 않음. |
| **운영 (배포된 서비스)** | **Cloudflare / Vercel / AWS 등 서버** | **해당 배포 서비스의 "환경 변수" 또는 "Secrets" 설정** | Vercel 대시보드 → Project → Settings → Environment Variables 에 같은 이름으로 값 등록 |

### 4.1 한 문장 요약

- **내 PC에서만 테스트하거나 개발할 때** → **`.env.local`**에 저장되어 있어야 하고,
- **운영 환경으로 클라우드에 배포했을 때** → 그 **배포 서비스(Cloudflare, Vercel 등)의 환경 설정(Environment Variables / Secrets)**에 등록되어 있어야 합니다.

로컬에는 로컬용, 운영에는 운영용을 **각각** 넣어 두어야 하며, 한쪽에만 있으면 그쪽에서만 동작합니다.

## 5. Google 서비스 계정 키(JSON) — 개념부터 적용까지

### 5.1 사람 계정 vs 서비스 계정

| 구분 | 설명 |
|------|------|
| **사람 계정** | Gmail 로그인할 때 쓰는 이메일·비밀번호. "누가" 로그인했는지 알 수 있음. |
| **서비스 계정** | **프로그램(앱·서버)**이 Google API를 쓰기 위한 계정. 사람이 로그인하는 게 아니라, **앱이 키(파일 또는 문자열)를 제출**해서 API를 쓰는 방식. |

**JSON 키 파일** = 그 **서비스 계정의 비밀키**가 담긴 파일. (비유: "앱 전용 출입증"을 파일로 받은 것)

### 5.2 "Vision API용 JSON을 받았다"는 뜻

- **Vision API** = Google이 제공하는 이미지 분석 등 API.
- **JSON 파일** = 그 API를 **우리 앱이 호출할 수 있게 해 주는 비밀키**가 들어 있는 파일.
- 따라서 **"Vision JSON 파일을 받았다" = "우리 앱이 Vision API를 쓸 수 있는 권한(키)을 받았다"**라고 이해하면 됩니다.

### 5.3 "적용된다" / "연결한다"의 의미

- **적용** = 프로그램이 실행될 때, 그 **키(파일 또는 환경변수에 넣은 JSON 내용)**를 읽어서 Google API 호출 시 사용하는 것.
- **연결** = 앱 설정(환경변수 등)에 **키 파일 경로** 또는 **키 내용**을 넣어서, 앱이 그 키를 찾아 쓰게 하는 것.

로컬에서는 보통 **파일 경로**를 환경변수에 넣고, 운영(Cloudflare/Vercel)에서는 **파일이 아니라 JSON 내용 자체**를 환경변수로 넣는 경우가 많습니다(아래 6장 참고).

### 5.4 JSON 파일은 어디에 두어야 하나? (로컬 기준)

- **반드시 안전한 곳**에만 둡니다. Git, 공개 폴더, 채팅/메일에는 **절대** 넣지 않습니다.
- **권한이 제한된 폴더**에 두고, **설정(.env.local)에는 경로만** 적습니다.  
  예:  
  - 파일 위치: `C:\Users\본인\secure-keys\habitree-vision-key.json`  
  - `.env.local`: `GOOGLE_APPLICATION_CREDENTIALS=C:/Users/본인/secure-keys/habitree-vision-key.json`

## 6. Cloudflare·Vercel 배포 시 주의점 (파일 경로 vs JSON 내용)

### 6.1 서버리스/엣지 환경의 특성

Cloudflare Workers, Vercel Serverless 등은 **일반 서버처럼 "파일을 업로드해 두고 그 경로를 준다"는 방식**을 쓰기 어렵습니다.  
빌드·배포 시 생성되는 파일만 있고, 우리가 올려 둔 `key.json` 같은 파일이 **항상 특정 경로에 있다고 보장되지 않습니다.**

### 6.2 그래서 운영에서는 "경로"가 아니라 "내용"을 넣는 경우가 많음

- **로컬**: `GOOGLE_APPLICATION_CREDENTIALS` = **파일 경로** (예: `C:/Users/.../key.json`)  
  → 프로그램이 그 경로의 파일을 읽음.
- **운영(Cloudflare/Vercel 등)**:  
  - `GOOGLE_APPLICATION_CREDENTIALS_JSON` 같은 **새 변수 이름**에,  
  - JSON 키 파일 **전체 내용을 한 줄 문자열**로 넣어 둠.  
  → 프로그램은 그 환경변수 값을 읽어서 `JSON.parse()` 한 뒤, Google 라이브러리에 **객체**로 넘김.

즉, **배포 서비스의 환경 설정에는 "키 파일의 내용(문자열)"을 등록**하고, **로컬에만 파일로 보관·경로를 .env.local에 적는 방식**으로 나누어 가져가는 경우가 많습니다.

### 6.3 정리

- **로컬**: `.env.local` + (선택) 로컬 디스크의 JSON 파일 경로.
- **운영(Cloudflare/Vercel)**: 해당 서비스의 **Environment Variables / Secrets**에 **JSON 내용 전체**를 값으로 등록.  
  로컬 PC에 JSON 파일이 없어도 **운영 서비스는** 그 플랫폼에 등록된 값만 있으면 동작합니다.

## 7. API·DB·연결 정보는 모두 같은 방식

API 키, DB URL, Supabase 키, Stripe 시크릿, GitHub 토큰, Google 서비스 계정 키 등 **외부 서비스와의 연결·인증에 쓰는 정보**는 **전부 같은 원칙**으로 관리합니다.

| 종류 | 로컬 | 운영(Cloudflare/Vercel 등) |
|------|------|----------------------------|
| Supabase URL / anon key / service_role key | `.env.local` | 해당 배포 서비스의 환경변수에 등록 |
| Google 서비스 계정 (JSON) | `.env.local`에 경로 또는, JSON 내용을 변수로 | 배포 서비스 환경변수에 **JSON 내용** 등록 |
| GitHub Personal Access Token | `.env.local` | 배포 서비스 환경변수에 등록 |
| Stripe 시크릿 키, 기타 API 키 | `.env.local` | 배포 서비스 환경변수에 등록 |

즉, **"환경변수에 대한 부분"**과 **"API·연결 정보"**는 **같은 방식으로 구성된다**고 보면 됩니다.  
로컬 = `.env.local`, 운영 = **해당 배포 서비스의 환경 설정**.

## 8. 로컬 PC와 서비스 동작의 관계

### 8.1 앱이 "내 로컬 PC"에서만 돌아가는 경우

- 키·환경변수는 **내 PC의 .env.local(또는 키 파일)**에만 있으면 됨.
- **로컬 PC가 꺼지면** 그 PC에서 돌리던 앱도 멈추므로, **그 서비스(예: Vision API 호출)도 동작하지 않습니다.**  
  → 이건 "키가 없어서"가 아니라 **"앱을 실행한 환경(내 PC)이 꺼진 것"** 때문입니다.

### 8.2 앱이 "Cloudflare·Vercel 등 서버"에서 돌아가는 경우

- 키·환경변수는 **배포 서비스의 환경 설정**에 등록되어 있어야 함.
- **내 로컬 PC가 꺼져 있거나, 로컬에 .env.local이 없어도** 상관없음.  
  → 서비스는 **서버**에서 돌아가고, 서버는 **자기 쪽 환경변수**만 읽기 때문입니다.
- **한 줄 요약**: 운영 서비스가 동작하는지 여부는 **"해당 배포 서비스(Cloudflare/Vercel 등)에 환경변수가 등록되어 있는가"**에만 달려 있고, **로컬 PC 상태와는 무관**합니다.

### 8.3 표로 정리

| 앱 실행 위치 | 키·환경변수를 둘 곳 | 로컬 PC가 꺼지면? |
|-------------|---------------------|-------------------|
| **내 PC** (로컬 개발) | `.env.local` 또는 로컬 키 파일 경로 | 그 PC에서 돌리던 앱만 멈춤 |
| **Cloudflare / Vercel 등** (운영) | 해당 서비스의 Environment Variables / Secrets | 서비스는 계속 동작 (로컬 PC와 무관) |

## 9. 실무 체크리스트

- [ ] **로컬**: API 키·DB URL·토큰·키 경로 등을 **`.env.local`**에만 두고, 이 파일은 **Git에 올리지 않기** (`.gitignore`에 포함)
- [ ] **운영**: 배포하는 플랫폼(Cloudflare, Vercel 등)의 **Environment Variables / Secrets**에 같은 이름으로 값 등록
- [ ] JSON 키 파일을 **프로젝트 폴더나 Git에 넣지 않기**. 로컬에서는 별도 폴더(예: `secure-keys`)에 두고 `.env.local`에는 **경로만** 적기
- [ ] 서비스가 **서버에서 돌아가면**, 키는 **반드시 서버(플랫폼) 쪽 환경변수·시크릿**에 두기. 로컬 PC만 의존하지 않기
- [ ] 키가 노출되었다고 생각되면 **즉시 로테이션(재발급·교체)** 하고, 노출된 키는 삭제·무효화

## 10. Google 서비스 계정 키 로테이션 절차 (예: Habitree Vision)

노출된 키는 삭제하고, 새 키를 발급한 뒤 **파일만 교체(또는 운영은 환경변수 값만 교체)** 하면 됩니다.

### 10.1 사전 확인

- **노출 위치**: `~/.claude/settings.json` Line 19 (제거 완료)
- **대상**: `readtree-vision-api-service@habitree-f49e1.iam.gserviceaccount.com` 서비스 계정의 비공개 키

### 10.2 로테이션 절차

1. [Google Cloud Console](https://console.cloud.google.com) 접속
2. 프로젝트: **habitree-f49e1** 선택
3. **IAM & Admin** → **Service Accounts** 이동
4. **readtree-vision-api-service** 계정 클릭
5. **Keys** 탭 → 노출된 키 ID `c9ca7c97d434...` **삭제**
6. **Add Key** → **Create New Key** → **JSON** 선택 후 다운로드
7. **로컬**: 새 JSON 파일을 안전한 위치에 저장 (예: `C:\Users\본인\secure-keys\habitree-vision-key-new.json`)  
   **운영**: JSON 파일 **내용 전체**를 복사해 둠
8. **로컬**: `.env.local`에 경로만 반영  
   ```bash
   GOOGLE_APPLICATION_CREDENTIALS=C:/Users/본인/secure-keys/habitree-vision-key-new.json
   ```  
   **운영**: Cloudflare/Vercel 등 해당 서비스의 환경변수에서 `GOOGLE_APPLICATION_CREDENTIALS_JSON`(또는 사용 중인 변수명) 값을 새 JSON 내용으로 교체
9. 앱 재시작(로컬) 또는 재배포/재시작(운영) 후 Vision API 호출이 정상인지 확인

## 11. 다른 크레덴셜 요약

- **GitHub Personal Access Token**: GitHub API·배포용. 노출 시 토큰 삭제 후 재발급하고, 로컬은 `.env.local`, 운영은 배포 서비스 환경변수에만 넣어 사용.
- **Supabase 키**: anon key / service_role key. Supabase 대시보드에서 Rotate 후, 로컬은 `.env.local`, 운영은 배포 서비스 환경변수에 반영.
- **Encryption Key (Linkmap 등)**: `openssl rand -hex 32`로 새 키 생성 후, 전용 로테이션 스크립트로 DB 등 반영. 로컬·운영 각각 `.env.local`과 배포 서비스 환경변수에 반영.

## 12. 자주 헷갈리는 것 Q&A

**Q. "로컬에 저장이 없어도 된다"가 맞나요?**  
A. **운영(배포된 서비스)**만 말하면 맞습니다. 운영에서는 배포 서비스의 환경변수에만 있으면 됩니다.  
   **로컬에서 개발·테스트할 때**는 그때 쓰는 앱이 **내 PC**에서 돌아가므로, **로컬의 .env.local(또는 키 파일)**이 있어야 합니다.

**Q. "API·연결 정보는 다 이런 식으로 구성된다"는 말이 맞나요?**  
A. 네. API 키, DB URL, 토큰, Google JSON 키 등 **연결·인증에 쓰는 정보**는 모두 **로컬 = .env.local, 운영 = 배포 서비스의 환경 설정**이라는 같은 방식으로 구성된다고 보면 됩니다.

**Q. Cloudflare/Vercel에 뭘 등록하나요? 파일 경로인가요, 내용인가요?**  
A. **JSON 키**처럼 "파일"로 쓰는 것은, 운영에서는 보통 **파일 경로가 아니라 JSON 내용 전체(문자열)**를 환경변수 하나에 넣습니다.  
   일반 API 키·URL·토큰은 **값 그대로** 환경변수에 등록하면 됩니다.

**Q. 내 PC가 꺼져 있어도 서비스가 돈다고 했는데, 키는 어디 있는 건가요?**  
A. **운영 서비스**가 Cloudflare/Vercel 등에서 돌 때, 키는 **그 플랫폼의 Environment Variables / Secrets**에 등록되어 있습니다.  
   그래서 **로컬 PC에는 없어도 되고**, PC가 꺼져도 **서버 쪽에 등록된 값**만 있으면 서비스는 계속 동작합니다.
