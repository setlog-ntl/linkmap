# 크레덴셜(인증 정보) 개념 가이드 — 초보자용

> **목적**: 설정 파일에 들어가는 "키", "토큰", "JSON 파일"이 무엇인지, 어디에 두고 어떻게 연결하는지 초보자도 이해할 수 있도록 정리한 문서입니다.  
> **공유용**: 팀원·다른 사용자에게 전달하여 함께 참고할 수 있습니다.

---

## 1. "크레덴셜"이란?

**크레덴셜(Credential)** = **외부 서비스를 사용할 때 "나(또는 우리 앱)가 권한이 있는 사용자다"라고 증명하는 비밀 정보**입니다.

- **비밀번호**, **API 키**, **JSON 키 파일**, **토큰** 등이 모두 크레덴셜의 일종입니다.
- 이 정보가 **설정 파일이나 코드에 그대로 적혀 있으면** 유출 위험이 있으므로, **별도 파일·환경변수·비밀 저장소**에 두고 **경로나 이름만** 설정에 적는 것이 좋습니다.

## 2. Google 서비스 계정 키(JSON 파일) — 쉽게 이해하기

### 2.1 사람 계정 vs 서비스 계정

| 구분 | 설명 |
|------|------|
| **사람 계정** | 우리가 Gmail 로그인할 때 쓰는 이메일/비밀번호. "누가" 로그인하는지 알 수 있음. |
| **서비스 계정** | **프로그램(앱·서버)**이 Google API를 쓰기 위한 계정. "사람이 로그인"하는 게 아니라 "앱이 키 파일을 들고 API를 호출"하는 방식. |

**JSON 키 파일** = 그 **서비스 계정의 비밀키**가 담긴 파일입니다.  
(비유: "앱 전용 출입증"을 파일로 받은 것)

### 2.2 "Vision API용 JSON을 받았다"는 뜻

- **Vision API** = Google이 제공하는 이미지 분석 등 기능.
- **JSON 파일** = 그 API를 **우리 앱이 사용할 수 있게 해 주는 비밀키**가 들어 있는 파일.
- 따라서 **"Vision JSON 파일을 받았다" = "우리 앱이 Vision API를 쓸 수 있는 권한(키)을 받았다"**라고 이해하면 됩니다.

### 2.3 "적용된다"는 게 무슨 의미인가?

**적용** = **우리 프로그램이 실행될 때, 그 JSON 파일(또는 그 내용)을 읽어서 Google API 호출 시 사용하는 것**입니다.

- 보통 **환경 변수**로 JSON **파일 경로**를 알려줍니다.  
  예: `GOOGLE_APPLICATION_CREDENTIALS=./my-key.json`
- 프로그램은 **실행되는 그 컴퓨터**에서 해당 경로의 파일을 찾아 읽고, 그 키로 Google에 인증합니다.
- 즉, **"연결한다" = "앱 설정(환경변수 등)에 키 파일 경로를 넣어, 앱이 그 파일을 찾아 쓰게 하는 것"**입니다.

### 2.4 JSON 파일은 어디에 두어야 하나?

- **반드시 안전한 곳**에만 둡니다.  
  - Git 저장소, 공개 폴더, 채팅/메일에 붙여넣기 하면 **절대 안 됩니다.**
- **권한이 제한된 폴더**에 두고, **설정에는 경로만** 적습니다.  
  예: `C:\Users\본인\secure-keys\habitree-vision-key.json`  
  → `.env.local`에는 `GOOGLE_APPLICATION_CREDENTIALS=C:/Users/본인/secure-keys/habitree-vision-key.json` 처럼 **경로만** 기입.

**정리**:  
- **파일** = 별도 보관, 로컬 또는 서버의 안전한 경로.  
- **연결** = 앱 설정(환경변수)에 그 **경로**를 넣어서, 앱이 그 파일을 읽어 쓰게 하는 것.

## 3. 로컬 PC에 저장해 두면 될까? PC가 꺼지면 서비스는?

여기서 중요한 건 **"앱이 어디에서 실행되는가"**입니다.

### 3.1 앱이 "내 로컬 PC"에서만 돌아가는 경우 (개발·테스트)

- JSON 키 파일을 **로컬 PC 한 곳**에 두고,  
  `GOOGLE_APPLICATION_CREDENTIALS`로 그 **경로**를 가리키면 됩니다.
- **로컬 PC가 꺼져 있으면** 그 PC에서 돌리던 프로그램도 멈추므로, **Vision API를 쓰는 그 앱도 동작하지 않습니다.**  
  → 이건 "키 관리" 문제가 아니라 **"앱을 실행한 환경(내 PC)이 꺼진 것"** 때문입니다.
- **정리**: 로컬에서만 쓸 때는 **로컬 PC에 키 보관 + 환경변수로 경로 연결**으로 관리하면 되고, PC가 꺼지면 그 PC에서 돌리던 서비스만 멈춥니다.

### 3.2 앱이 "클라우드·서버"에서 돌아가는 경우 (실제 서비스)

- 실제 서비스는 **내 PC가 아니라** AWS, GCP, Cloudflare 등 **서버**에서 돌아갑니다.
- 그 서버는 **내 PC의 C: 드라이브**를 볼 수 없습니다.  
  → 따라서 **키 파일을 로컬 PC에만 두면**, 배포된 서비스에서는 그 키를 읽을 수 없어 **Vision API 호출이 실패**합니다.
- 서비스가 24시간 동작하려면 **그 서버가 접근할 수 있는 곳**에 키를 둬야 합니다.  
  예:  
  - 서버 디스크의 특정 경로에 JSON 파일 배치 후 `GOOGLE_APPLICATION_CREDENTIALS`로 그 경로 지정  
  - 또는 JSON **내용**을 **시크릿(환경 변수·Secret Manager)**으로 넣고, 코드에서 환경 변수에서 읽도록 구현

이 경우 **내 로컬 PC가 꺼져 있거나 문제가 있어도, 서버에서 돌아가는 서비스는 계속 동작합니다.**  
서비스 동작 여부는 **"서버가 키를 가지고 있는가"**에만 달려 있고, 로컬 PC와는 무관합니다.

### 3.3 한 줄 요약

| 앱 실행 위치 | 키 보관 위치 | 로컬 PC가 꺼지면? |
|-------------|--------------|-------------------|
| **내 PC** (로컬 개발) | 로컬 PC 안전한 경로 | 그 PC에서 돌리던 앱만 멈춤 (당연) |
| **서버/클라우드** (배포 서비스) | 서버 또는 시크릿 저장소 | 서비스는 계속 동작 (로컬 PC와 무관) |

## 4. 실무 체크리스트 — 키 파일 관리

- [ ] JSON 키 파일을 **프로젝트 폴더나 Git에 넣지 않기**
- [ ] **별도 폴더**(예: `secure-keys`)에 저장하고, 설정에는 **경로만** 적기
- [ ] 서비스가 **서버에서 돌아가면**, 키는 **서버/시크릿 저장소**에 두고, 로컬 PC만 의존하지 않기
- [ ] 키가 노출되었다면 **즉시 로테이션(재발급·교체)** 하기

## 5. Google 서비스 계정 키(예: Habitree Vision) 로테이션 절차

노출된 키는 삭제하고, 새 키를 발급해 **파일만 교체·경로는 그대로** 두는 방식으로 적용할 수 있습니다.

### 5.1 사전 확인

- **노출 위치**: `~/.claude/settings.json` Line 19 (제거 완료)
- **대상**: `readtree-vision-api-service@habitree-f49e1.iam.gserviceaccount.com` 서비스 계정의 비공개 키

### 5.2 로테이션 절차

1. [Google Cloud Console](https://console.cloud.google.com) 접속
2. 프로젝트: **habitree-f49e1** 선택
3. **IAM & Admin** → **Service Accounts** 이동
4. **readtree-vision-api-service** 계정 클릭
5. **Keys** 탭 → 노출된 키 ID `c9ca7c97d434...` **삭제**
6. **Add Key** → **Create New Key** → **JSON** 선택 후 다운로드
7. 새 JSON 파일을 **안전한 위치**에 저장 (예: `C:\Users\본인\secure-keys\habitree-vision-key-new.json`)
8. 프로젝트 `.env.local`(또는 사용 중인 설정)에 **경로만** 반영:
   ```bash
   GOOGLE_APPLICATION_CREDENTIALS=C:/Users/본인/secure-keys/habitree-vision-key-new.json
   ```
9. 앱 재시작 후 Vision API 호출이 정상인지 확인

## 6. 다른 크레덴셜 요약 (참고)

- **GitHub Personal Access Token**: GitHub API/배포용. 노출 시 삭제 후 재발급하고, 환경변수 등에만 넣어 사용.
- **Supabase 키**: anon key / service_role key. 대시보드에서 Rotate 후 `.env` 등에 반영.
- **Encryption Key (Linkmap 등)**: `openssl rand -hex 32`로 새 키 생성 후, 전용 로테이션 스크립트로 DB 등 반영하고 `.env` 갱신.

자세한 절차는 팀 내 **Credential Rotation Guide** 문서를 참고하면 됩니다.
