크레덴셜(Credential) = 외부 서비스를 사용할 때 "나(또는 우리 앱)가 권한이 있는 사용자다"라고 증명하는 비밀 정보입니다.

이 정보가 코드나 공개 설정에 그대로 적혀 있으면 유출 위험이 있으므로, 별도 파일(.env.local)이나 비밀 저장소에 두고 코드에는 변수 이름만 적는 것이 원칙입니다.

유출 시 대응: 키 로테이션

키가 유출되었다면 즉시 로테이션(재발급 + 교체)이 필요합니다. 기존 키를 삭제하고 새 키를 발급한 뒤, 파일만 교체하는 방식입니다.

  1. 해당 서비스 콘솔에서 노출된 키 즉시 삭제/무효화
  2. 새 키를 발급받아 안전한 위치에 저장 (Git 저장소 외부)
  3. 로컬: .env.local에 새 값 반영
  4. 운영: 배포 서비스(Cloudflare/Vercel)의 Environment Variables에서 교체
  5. 앱 재시작 후 정상 동작 확인

.env 파일의 한계 — 7가지 구조적 문제

환경변수(Environment Variable)는 프로그램이 실행되는 환경에서 "이름 = 값" 형태로 넣어 두는 설정값입니다. 비밀값을 코드에 직접 쓰지 않기 위해 사용하지만, .env 파일 자체에는 근본적인 한계가 있습니다.

1. 동기화 없음
팀원 A가 변수를 추가해도, 팀원 B의 로컬 .env에는 반영되지 않음. "내 환경에서는 되는데?"의 주범
2. 버전 관리 불가
.env는 .gitignore에 포함되므로 변경 이력을 추적할 수 없음. 누가, 언제, 왜 바꿨는지 알 수 없음
3. 암호화 부재
평문 텍스트 파일이므로, 디스크 접근 권한이 있으면 누구나 읽을 수 있음
4. 환경별 분리 어려움
.env.local, .env.production, .env.staging... 파일이 늘어나며 어떤 값이 어느 환경에 적용되는지 혼란
5. 접근 제어 불가
인턴이든 CTO든 .env 파일에 접근하면 모든 시크릿을 볼 수 있음. 역할별 권한 분리 불가
6. 감사 로그 없음
누가 어떤 변수를 조회하거나 수정했는지 추적 불가. 보안 사고 발생 시 원인 파악 어려움
7. 자동 로테이션 불가
키 만료나 유출 시 모든 환경의 .env를 수동으로 일일이 수정해야 함

로컬 vs 운영 — 반드시 구분해야 하는 이유

구분 로컬 (개발) 운영 (프로덕션)
실행 위치 내 PC (npm run dev) Cloudflare / Vercel / AWS 서버
크레덴셜 위치 .env.local + 로컬 키 파일 배포 서비스의 Environment Variables
PC 꺼지면? 앱도 멈춤 서비스는 계속 동작 (로컬 PC와 무관)

서버리스/엣지 환경에서는 "파일을 업로드해 두고 경로를 주는" 방식이 통하지 않습니다. key.json 파일이 특정 경로에 있다고 보장되지 않기 때문입니다.

바이브 코딩과 보안 위기

바이브 코딩(Vibe Coding)이란?

Andrej Karpathy가 2025년 2월 명명한 새로운 코딩 방식. AI 도구(Cursor, Copilot, Bolt 등)에게 자연어로 지시하여 코드를 생성하고, 개발자는 코드를 직접 작성하기보다 "결과가 되면(vibes) 수용"하는 프로그래밍 패러다임.

Collins Dictionary는 "vibe"를 2025 올해의 단어로 선정했으며, 바이브 코딩은 개발의 진입 장벽을 극적으로 낮추고 있습니다.

멀티서비스 오케스트레이션

현대 SaaS 앱은 평균 10개 이상의 외부 서비스에 의존합니다. 인증(Auth0/Supabase), 결제(Stripe), 이메일(SendGrid), 검색(Algolia), 모니터링(Sentry), AI(OpenAI), 스토리지(S3), CDN(Cloudflare), CI/CD(GitHub Actions), 분석(Mixpanel)... 각 서비스마다 API 키, 웹훅 URL, 연결 설정이 필요합니다.

서비스 10개 × 환경 3개 (dev/staging/prod) × 변수 3~5개/서비스 = 90~150개의 환경변수를 관리해야 함

왜 시각화가 필수인가?

의존성 파악
"결제 서비스를 교체하면 어디에 영향이 있지?" — 서비스맵이 없으면 코드를 하나하나 grep 해야 합니다.
장애 범위 추적
"Supabase가 다운되면 우리 서비스 중 뭐가 멈추지?" — 연결 관계를 한눈에 파악해야 빠른 대응이 가능합니다.
신규 팀원 온보딩
"우리 서비스가 뭘 쓰고 있지?" — 서비스맵 하나로 전체 아키텍처를 5분 안에 이해할 수 있습니다.
AI 에이전트 시대의 서비스 관리

2025-2026년, AI 에이전트가 API를 직접 소비하는 시대가 열리고 있습니다. Anthropic의 MCP(Model Context Protocol), OpenAI의 Function Calling이 표준화되면서 AI가 서비스 연결 정보를 직접 조회하는 워크플로우가 현실이 되었습니다.

Linkmap MCP Server는 AI 에이전트가 프로젝트의 서비스 목록, 환경변수, 연결 상태를 안전하게 조회할 수 있게 합니다. 코드 생성 시 올바른 환경변수 이름을 사용하고, 누락된 설정을 자동으로 감지합니다.

실무 체크리스트 — 키 & 환경변수 관리

로컬 환경
  • API 키, DB URL, 토큰을 .env.local에만 두기
  • .gitignore에 .env* 패턴 포함 확인
  • JSON 키 파일은 프로젝트 외부 폴더에 보관
  • 설정에는 경로만 기입 (값 하드코딩 금지)
운영 환경
  • 배포 플랫폼의 Environment Variables / Secrets에 등록
  • JSON 키는 내용 전체를 문자열로 등록 (경로 아님)
  • 키 유출 시 즉시 로테이션 (재발급 + 교체)
  • 로컬 PC 의존 금지 — 서버는 서버 쪽 환경변수만 읽음

자주 묻는 질문

Q. 로컬에 .env가 없어도 운영 서비스가 돌아가나요?
네. 운영 서비스는 배포 플랫폼(Cloudflare/Vercel)의 환경변수만 읽으므로, 로컬 .env 파일과는 무관합니다. 로컬 PC가 꺼져 있어도 운영 서비스는 계속 동작합니다.
Q. Cloudflare/Vercel에 파일 경로를 넣어야 하나요, 내용을 넣어야 하나요?
서버리스 환경은 특정 파일 경로를 보장하지 않으므로, JSON 키 파일의 경우 내용 전체(문자열)를 환경변수에 등록합니다. 일반 API 키, URL, 토큰은 값 그대로 등록하면 됩니다.
Q. 모든 API·DB 연결 정보가 같은 방식으로 관리되나요?
네. Supabase 키, Stripe 시크릿, GitHub 토큰, Google JSON 등 모든 연결 정보는 동일한 원칙입니다: 로컬 = .env.local, 운영 = 배포 서비스의 환경 설정.

Linkmap 솔루션 — 문제를 구조적으로 해결

문제 → 해결

문제: 시크릿 유출
23.8M건의 시크릿이 GitHub에 유출
→
해결: AES-256-GCM 암호화
유저가 키를 보유하는 클라이언트 사이드 암호화. 서버도 평문에 접근 불가.
문제: .env 동기화 실패
팀원 간 환경변수 불일치
→
해결: 중앙 환경변수 관리
프로젝트 단위로 환경변수를 중앙 관리. GitHub Secrets 양방향 동기화.
문제: 서비스 의존성 파악 불가
10+ 외부 서비스 연결 관계를 아무도 모름
→
해결: 서비스맵 시각화
React Flow 기반 3-Level View (Status/Map/Dependency). 전체 아키텍처를 한눈에.
문제: 바이브 코딩 보안 위기
AI 생성 코드의 40%+에 보안 결함
→
해결: MCP Server + Env Doctor
AI 에이전트가 안전하게 환경변수 참조. 설정 오류 자동 진단.
문제: 온보딩 6주 소요
신규 개발자 셋업에 $75K+ 인건비 손실
→
해결: 서비스맵 + 자동 매핑
초대만으로 전체 아키텍처 파악. 환경변수 자동 접근. 1주 내 생산성.
문제: GitHub 멀티 계정 혼란
개인/업무 계정 시크릿 관리 분리 불가
→
해결: GitHub 멀티 계정 연결
다중 GitHub 계정 연결 + 프로젝트별 선택 + 시크릿 동기화.
문제: 반복적 배포 설정
새 프로젝트마다 동일한 서비스 연결 작업 반복
→
해결: 원클릭 배포 + 템플릿
모듈 에디터로 커스텀 템플릿 구성. GitHub Pages 원클릭 배포.

핵심 기능

🗺️
서비스맵
React Flow 기반 인터랙티브 맵. 3-Level View: Status(대시보드), Map(연결 시각화), Dependency(의존성 분석). Zone 기반 레이아웃으로 서비스를 논리적으로 그룹핑.
🔒
AES-256-GCM 암호화
유저가 암호화 키를 보유하는 클라이언트 사이드 암호화. 서버는 암호문만 저장하며 평문에 접근할 수 없는 구조. 64 hex chars 키로 엔터프라이즈급 보안.
🐙
GitHub 멀티 계정
다중 GitHub 계정 연결. 프로젝트별 계정 선택. GitHub Secrets 양방향 동기화. 리포지토리 기반 서비스 자동 매핑.
🤖
AI 기능 (5개)
Stack Recommend: 기술 스택 추천. Env Doctor: 환경변수 진단. Map Narrate: 서비스맵 설명 생성. Compare Services: 서비스 비교 분석. NL Command: 자연어 명령 실행.
🔌
MCP Server
Cursor, Claude Code 등 AI 에이전트와 직접 연동. 서비스 목록, 환경변수, 연결 상태를 안전하게 조회. 바이브 코딩 시 보안 가드레일 역할.
🚀
원클릭 배포
모듈 에디터로 서비스 템플릿 커스터마이징. GitHub Pages 원클릭 배포. 서비스 설정 자동 구성으로 반복 작업 제거.
바이브 코더를 위한 Linkmap

AI와 함께 안전하게 빌드

  • MCP Server: AI가 환경변수를 안전하게 참조하여 하드코딩 원천 차단
  • Env Doctor: AI 생성 코드의 환경변수 설정 오류를 자동 감지
  • Stack Recommend: 프로젝트에 맞는 서비스 조합을 AI가 추천

속도를 희생하지 않는 보안

  • 서비스맵: 연결 구조를 시각적으로 즉시 파악
  • 원클릭 배포: 반복적인 설정을 템플릿으로 자동화
  • GitHub 동기화: 시크릿을 수동으로 복사/붙여넣기할 필요 없음

가입 & 로그인

3
서비스맵 확인
서비스맵에서 전체 아키텍처를 시각적으로 확인. 환경변수를 안전하게 관리하고 팀원과 공유.
