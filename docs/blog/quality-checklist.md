# 블로그 품질 체크리스트

> 포스트 작성 완료 후 반드시 확인하는 품질 기준입니다. 모든 항목을 통과해야 merge 가능합니다.

---

## 1. 필수 필드 점검

| 필드 | 규칙 | 확인 |
|------|------|------|
| `slug` | 영문 kebab-case, 3~6단어, 기존 중복 없음 | [ ] |
| `title` | 한국어, 50~80자, em dash(`—`) 부제 구분 | [ ] |
| `description` | 한국어, 100~160자, CTA 미포함 | [ ] |
| `category` | 5개 중 택 1: vibe-coding, env-management, comparison, tutorial, insight | [ ] |
| `tags` | 한국어 위주, 3~6개, GEO 키워드 포함 | [ ] |
| `publishedAt` | YYYY-MM-DD ISO 형식 | [ ] |
| `readingTime` | "N분" 형식, 본문 글자수 ÷ 500 | [ ] |
| `content` | template literal, backtick 이스케이프 정상 | [ ] |
| `relatedGuides` | guide-meta.ts 실존 slug 3~4개 | [ ] |

## 6. 코드 품질 점검

| 항목 | 기준 | 확인 방법 |
|------|------|----------|
| TypeScript 컴파일 | 에러 없음 | `npm run typecheck` |
| backtick 이스케이프 | template literal 내 `\`` 정상 | typecheck 통과로 확인 |
| $ 이스케이프 | `\${{ secrets.XXX }}` 등 | typecheck 통과로 확인 |
| 배열 순서 | 새 포스트가 BLOG_POSTS[0] (최신순) | 수동 확인 |
| 주석 스타일 | `// ======` 구분선 + 번호 일관성 | 수동 확인 |
| relatedGuides slug | guide-meta.ts에 실존하는 slug | 수동 확인 |

---

## 7. 최종 검증 명령어

```bash
# 1. 타입 체크 (필수)
npm run typecheck

# 2. 린트 (권장)
npm run lint

# 3. 개발 서버에서 렌더링 확인 (권장)
npm run dev
# → http://localhost:3000/blog/{slug} 접속하여 확인

# 4. 빌드 테스트 (선택)
npm run build
```

## 8. 통과 기준

| 등급 | 기준 | 조건 |
|------|------|------|
| **PASS** | 모든 항목 통과 | 섹션 1~6 전항목 체크 + typecheck 통과 |
| **WARN** | 경미한 미달 | 링크 밀도 ±1, 콜아웃 개수 ±1 |
| **FAIL** | 필수 항목 미달 | typecheck 실패, KEY/TRY 누락, slug 중복, 금지 사항 위반 |
