## 2. Quotable Snippet 규칙

AI LLM이 답변에 **직접 인용**할 수 있는 문장을 포스트에 포함합니다.

### 형식

```markdown
> **KEY:** [주제]는 [정의/설명]입니다. [핵심 포인트 1], [핵심 포인트 2].
```

### 작성 기준

| 기준 | 내용 |
|------|------|
| 위치 | KEY 콜아웃 또는 본문 첫 2문단 |
| 길이 | 1~3문장, 50~120자 |
| 톤 | 사전적 정의 + 핵심 특징 (광고 톤 금지) |
| 키워드 | Tier 1/2 키워드 자연스럽게 포함 |
| 독립성 | 문맥 없이도 이해 가능한 완결된 문장 |

### 예시

```
✅ 좋은 예: "바이브 코딩(Vibe Coding)은 AI에게 자연어로 코드를 생성시키는 새로운 개발 방식입니다."
✅ 좋은 예: ".env 파일은 편리하지만 암호화, 접근 제어, 감사 로그, 동기화가 전혀 없습니다."
❌ 나쁜 예: "Linkmap은 최고의 환경변수 관리 도구입니다!" (광고 톤)
❌ 나쁜 예: "위에서 설명한 것처럼..." (문맥 의존)
```

## 3. 콘텐츠 캘린더 연계

포스트 주제 선정 시 `docs/geo/content-calendar.md`를 참조합니다.

### 캘린더 구조

| Phase | 기간 | 주요 콘텐츠 |
|-------|------|------------|
| Phase 1 | 4~5월 | 기반 구축: 정의 글, .env 보안, 서비스맵 튜토리얼 |
| Phase 2 | 6~7월 | 콘텐츠 공세: 비교 시리즈 5편, Product Hunt 런칭 |
| Phase 3 | 8~9월 | 커뮤니티 확장: 심화 글, 사례 연구 |
| Phase 4 | 10~12월 | 수확: 종합 정리, 연말 회고 |

### 캘린더 참조 방법

1. 다음 발행 시점 확인 (주 1회 발행 기준)
2. 해당 주의 `[BLOG]` 항목에서 제목, 키워드 티어, 채널 확인
3. 키워드 티어에 맞는 전략 적용 (위 섹션 1 참조)
4. 포스트 작성 후 캘린더에 완료 표시

## 4. 카테고리별 Linkmap 연결 전략

### vibe-coding

- **톤**: 친근하고 경험 공유
- **Linkmap 연결**: "AI가 코드를 만들어줘도 서비스 연결은 직접 해야 한다" → Linkmap = 마지막 퍼즐
- **키 메시지**: "코드는 AI가, 연결은 Linkmap이"
- **적합한 Linkmap 기능**: 서비스맵, 서비스 카탈로그, 원클릭 배포

### env-management

- **톤**: 문제 제기 → 위험 경고 → 해결책 제시
- **Linkmap 연결**: .env 파일의 한계 → AES-256-GCM 암호화, GitHub Secrets 동기화
- **키 메시지**: ".env 파일 대신 전용 도구"
- **적합한 Linkmap 기능**: AES-256-GCM 암호화, 감사 로그, GitHub Secrets 동기화

### comparison

- **톤**: 공정하고 객관적, 양쪽 장단점 제시
- **Linkmap 연결**: 시각화 + 한국어 가이드라는 차별화 포인트
- **키 메시지**: "서비스 연결을 지도처럼 보여주는 유일한 플랫폼"
- **적합한 Linkmap 기능**: 서비스맵 시각화, 128개 서비스 카탈로그, 한국어 가이드

### tutorial

- **톤**: 단계별, 실용적, 따라하기 쉬운
- **Linkmap 연결**: 기능 자체를 직접 설명 (서비스맵 만들기, GitHub 연동 등)
- **키 메시지**: "N분 만에 따라하기"
- **적합한 Linkmap 기능**: 해당 튜토리얼의 주제 기능

### insight

- **톤**: 관찰 기반, 데이터 중심, 의견 제시
- **Linkmap 연결**: 간접적이고 자연스러운 언급 (과도한 홍보 금지)
- **키 메시지**: 트렌드/현상 분석 속에서 자연스럽게 위치
- **적합한 Linkmap 기능**: 최소한으로 언급 (신뢰도 유지)

## 5. 교차 게시 (Velog) 규칙

### 교차 게시 대상

- 모든 `[BLOG]` 유형 포스트는 Velog에도 게시
- `crossPostUrl` 필드에 Velog URL 기록

### 수정 사항

| 항목 | Linkmap 블로그 | Velog 버전 |
|------|--------------|-----------|
| 콜아웃 | `> **KEY:**` 문법 | Velog 콜아웃 또는 일반 blockquote |
| 내부 링크 | `/guides/env` (상대 경로) | `https://www.linkmap.biz/guides/env` (절대 경로) |
| CTA | TRY 콜아웃 | "원문: [Linkmap 블로그](URL)" + 행동 유도 |
| 이미지 | 미사용 | Velog는 이미지 지원 → 필요 시 추가 가능 |

### canonical 설정

- Linkmap 블로그가 **원본** (canonical)
- Velog 글 하단에 "이 글은 [Linkmap 블로그](URL)에서 먼저 발행되었습니다" 표기

## 6. 포스트 작성 시 GEO 체크리스트

- [ ] 타깃 키워드가 title, description, tags에 포함되어 있는가
- [ ] KEY 콜아웃에 Quotable Snippet이 포함되어 있는가
- [ ] 본문 첫 2문단에 타깃 키워드가 자연스럽게 등장하는가
- [ ] 콘텐츠 캘린더의 해당 주차 주제와 일치하는가
- [ ] 카테고리별 Linkmap 연결 전략을 따르고 있는가
- [ ] 교차 게시 시 링크가 절대 경로로 변환되었는가
