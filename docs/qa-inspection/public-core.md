## 분석 및 권장사항

### 근본 원인
Cloudflare Workers Free Plan의 CPU 10ms 제한으로 인한 Error 1102. 캐시가 없는(cold) 페이지 요청 시 서버 렌더링이 CPU 한도를 초과하여 503 응답.

### 정상 동작한 페이지의 공통점
- `/`, `/pricing`, `/services`, `/services/*`, `/blog`, `/blog/vibe-coding-social-login-guide` -- 모두 캐시 워밍이 되어있거나, `revalidate = false`로 정적 캐시된 페이지.

### 실패한 페이지의 공통점
- `/demo/*`, `/showcase`, `/faq`, `/glossary`, `/feedback`, `/terms`, `/privacy`, `/login`, `/signup`, `/reset-password` -- 캐시가 만료되었거나 워밍되지 않은 페이지.

### 즉시 조치 필요 (P0)
1. **캐시 워밍 실행**: `bash scripts/warm-cache.sh` 로 모든 공개 페이지 캐시 워밍
2. **로그인/회원가입 페이지**: 신규 사용자 유입이 완전 차단 상태. 최우선 복구 필요.
3. **법적 페이지 (`/terms`, `/privacy`)**: 법적 준수 관점에서 항시 접근 가능해야 함.

### 중기 개선 (P1)
1. `/demo/*` 경로에 `revalidate = false` 또는 ISR 적용 검토
2. `/login`, `/signup` 등 인증 페이지의 `force-dynamic` 설정이 Workers Free Plan과 충돌하는지 확인
3. CI/CD 배포 후 자동 캐시 워밍이 정상 동작하는지 점검
4. `/services/compare` 비교표 데이터("-")가 의도적인지 확인

### 네트워크 참고사항
- Google Analytics, Clarity, Cloudflare RUM의 `ERR_ABORTED`는 페이지 전환 시 발생하는 정상 동작으로, 실제 문제가 아님.
- Supabase API 호출(`/auth/v1/user`, `/rest/v1/services`, `/rest/v1/profiles`)은 모두 200 정상 응답.
