P0 즉시 조치 (당일 완료)

▼
P0-1. warm-cache.sh 누락 경로 추가
CRITICAL S 인프라
이슈: warm-cache.sh에 12개 경로만 등록 → 30개 페이지 503
원인: /signup, /reset-password, /terms, /faq, /glossary, /demo/project/* 등 누락
조치: PAGES 배열에 누락된 공개 페이지 전체 추가. /login, /signup, /terms, /privacy, /demo/* 우선
P0-2. 즉시 캐시 워밍 실행
CRITICAL S 인프라
이슈: 배포 후 캐시 워밍 미실행 → 30개 페이지 접근 불가
원인: 수동 배포 시 워밍 스크립트 미실행
조치: bash scripts/warm-cache.sh https://linkmap.biz 즉시 실행 후 실패 경로 재확인
P0-3. /login, /signup 렌더링 전략 검토
CRITICAL M 프론트엔드
이슈: 인증 페이지 503 → 신규 사용자 유입 완전 차단
원인: force-dynamic 또는 캐시 미적용으로 매 요청마다 CPU 10ms 초과
조치: 인증 폼은 클라이언트 컴포넌트이므로 페이지 셸을 revalidate = false 정적화 검토. Supabase Auth는 클라이언트에서 호출하므로 서버 측 동적 렌더링 불필요 가능
P0-4. /terms, /privacy 페이지 가용성 확보
CRITICAL S 인프라 / 프론트엔드
이슈: 법적 준수 페이지 접근 불가
원인: /terms 누락 + 캐시 만료 후 503
조치: 경로 추가 + 두 페이지 모두 revalidate = false 정적 빌드 확인

P1 단기 개선 (1주 이내)

▼
P1-1. 503 에러 시 사용자 친화적 fallback UI
CRITICAL M 프론트엔드
이슈: Workers 503 발생 시 Cloudflare 기본 에러 페이지 노출 (브랜드 경험 단절)
조치: 커스텀 에러 페이지 구현. "잠시 후 다시 시도해주세요" 메시지 + 자동 새로고침 옵션
P1-2. /project/[id]/integrations 리다이렉트 수정 (C2)
CRITICAL M 프론트엔드 / 백엔드
이슈: 통합 페이지 → 가이드 리다이렉트 + 인증 세션 유실
조치: 에러 핸들링 강화 + 503 시 리다이렉트 방지 + 인증 세션 유지 확인
P1-3. /services/compare 비교 데이터 보완 (W1)
WARNING M 데이터 / 프론트엔드
이슈: 비교표 핵심 데이터(타입, 무료 티어, DX 점수)가 모두 "-" 표시
조치: 비교 데이터 소스 확인 + 누락 필드 보완 + UI 데이터 바인딩 검증
P1-4. CI/CD 배포 후 자동 캐시 워밍 확인
CRITICAL S 인프라 / DevOps
이슈: 배포 후 캐시 워밍이 안정적으로 실행되지 않을 가능성
조치: CI/CD 설정 확인 + 배포 완료 대기 후 실행 + 워밍 실패 시 알림
P1-5. /project/[id]/audit 리다이렉트 확인 (W2)
WARNING S 프론트엔드
이슈: 감사 로그 페이지가 /settings로 리다이렉트
조치: 의도적 리다이렉트인지 버그인지 확인 후 적절히 처리
P1-6. /project/[id]/health 빈 콘텐츠 수정 (W3)
WARNING M 프론트엔드
이슈: 헬스 체크 페이지가 빈 화면으로 렌더링
조치: empty state UI 추가 + API 에러 메시지 표시 + 설정 안내 CTA

P3 장기 개선 (1~3개월)

▼
P3-1. Workers Paid Plan 전환 검토
S(기술) L(비즈니스) 인프라 / 경영
이슈: Free Plan CPU 10ms 제한이 503의 근본 원인
조치: Paid Plan ($5/mo, CPU 50ms) 전환 시 비용 대비 효과 분석 + 트래픽 증가 시뮬레이션
P3-2. 에러 모니터링 시스템 도입
L 인프라
이슈: 503 에러 사전 감지 불가 (Sentry 삭제 후 대체 미도입)
조치: Cloudflare Analytics/Logpush 활용 + 503 자동 감지 → warm-cache 트리거
P3-3. 페이지 성능 예산(Performance Budget) 수립
L 프론트엔드 / DevOps
이슈: Workers CPU 제한 하에서 페이지별 성능 관리 체계 부재
조치: 서버 번들 크기 상한 설정 + CI 자동 감지 + 신규 페이지 CPU 테스트 체크리스트
P3-4. 자동화된 QA 파이프라인 구축
L QA / DevOps
이슈: 수동 QA 점검 의존 → 회귀 감지 지연
조치: Playwright 스모크 테스트 30개 페이지 + 배포 후 자동 실행 + 실패 시 롤백/알림
