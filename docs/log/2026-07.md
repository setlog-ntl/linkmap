- **진단:**
  - Supabase 키 로테이션(6-21 P0 인시던트 대응, 레거시 JWT → `sb_publishable_`) **완료 확인** — 로컬 `.env.local`·라이브 번들(`linkmap.biz` 청크) 모두 신형 키로 일치, REST/Auth 엔드포인트 신형 키로 200 정상.
  - 문제는 **로테이션 이전에 로그인한 브라우저의 세션 쿠키(구 JWT 서명)가 좀비로 잔존** — 무효 토큰이 Authorization으로 계속 전송돼 전면 401(로그인 화면의 401은 전역 CommandPalette의 `useCatalogServices`가 발사). 미들웨어·클라이언트 어디에도 죽은 세션 정리 로직이 없어 자가복구 불가, 재로그인도 오염된 쿠키 상태에서 불안정.
  - 부가 발견: 미들웨어가 리다이렉트 시 갱신된 세션 쿠키를 유실 → 브라우저가 이미 소비된 refresh token 재사용 → Supabase 재사용 감지로 세션 강제 종료(간헐 로그아웃의 또 다른 원인).
- **결과:**

  - **`session.ts`(미들웨어)**: 인증 쿠키 존재 + 확정적 인증 실패 시 `sb-*-auth-token*` 쿠키 자동 만료(자가치유) — 다음 요청부터 깨끗한 비로그인 상태 복구. 리다이렉트 응답에 회전된 토큰 쿠키 전달(`copyResponseCookies`). silent catch 제거(console.error + fail-open).
  - **`providers.tsx`**: QueryCache/MutationCache 전역 onError로 확정 인증 실패 시 local signOut + 보호 경로면 `/login` 전체 리로드(미들웨어 경유로 서버측 쿠키 정리 보장). 초기 마운트 시 세션 존재하면 `getUser()` 1회 서버 검증 → 무효면 즉시 정리. retry 가드에 `isDefinitiveAuthFailure` 추가(기존 `message.includes('401')`은 PostgrestError "JWT expired"를 놓침).
  - 검증: 신규 테스트 20개(auth-recovery 11 + session 9) 포함 전체 vitest 260/260 통과 · typecheck 0 errors · 변경 파일 lint clean.
- **인사이트:** 키 로테이션은 "서버 측 완료"가 끝이 아니라 **기존 사용자 브라우저의 좀비 세션 정리까지가 마이그레이션** — 미들웨어에 확정적 인증 실패 → 쿠키 만료 경로가 없으면 로테이션마다 전 사용자가 수동 쿠키 삭제를 해야 한다. 콘솔의 CSP connect-src 위반은 Report-Only(차단 없음)로 본 건과 무관.

### 2026-07-31 — 원클릭 모듈 에디터 이미지 고도화: 무손실 표시(contain) + 업로드 크롭 편집
- **카테고리:** #기능 #원클릭 #UX
- **중요도:** P1
- **지시:** "원클릭배포의 모듈편집기능에서 이미지 선택시 해당이미지가 잘리지 않고 원본이미지를 해당크기로 그대로 적용되도록하며 이미지 업로드이후 간단하게 자르기로 적용편집할수있는기능 고도화진행".
- **진단:** 잘림의 원인은 업로드 파이프라인이 아니라 **템플릿 CSS**(고정 `aspect-ratio` + `object-fit: cover` → 항상 중앙 크롭)였다. 업로드는 비율 유지 축소(장변 1200px→WebP)만 수행. 또한 스키마에 image 타입이 없어 이미지 필드와 일반 URL(kakaoMapUrl 등)이 전부 `url`로 섞여 업로드 버튼이 비이미지 필드에도 붙어 있었다.
- **결과:**
  - **`type: 'image'` 신설** (`src/lib/module-schema.ts`) + `imageAspect` 힌트(슬롯 비율, 예: '3/4'). `module-form.tsx`에서 image→업로드+크롭 UI, url→순수 입력(`PlainUrlInput`, 위험 프로토콜 차단·https 자동부착 유지)으로 분리. 8개 모듈 스키마의 이미지 필드 13곳 전환(히어로·아바타·갤러리·메뉴·포트폴리오), 지도·SNS·RSVP 링크는 url 유지. 배열 아이템 업로드에 `onImagePreview` 미전달로 갤러리 업로드가 프리뷰에 안 뜨던 기존 갭도 함께 연결.
  - **크롭 다이얼로그** (`image-crop-dialog.tsx`, react-easy-crop@6.2.3 신규 의존성): 파일 선택/드롭 → 다이얼로그 오픈 → "사이트 비율(스키마 imageAspect)"·원본 비율·1:1·4:3·3:4·16:9 프리셋 + 드래그·줌 → "잘라서 적용" 또는 **"자르지 않고 원본 사용"**. 크롭 결과는 canvas로 베이크되어 기존 리사이즈→WebP→GitHub 업로드 파이프라인을 그대로 통과(config.ts에는 여전히 경로 문자열만 → 라운드트립 대칭성에 영향 없음). 기존 이미지 미리보기에 재크롭 버튼 추가(세션 내 업로드본·CORS 허용 URL만 가능, 배포 경로는 재업로드 안내).
  - **무손실 표시 정책**: 콘텐츠 이미지 슬롯을 `object-fit: contain` + 중립 레터박스 배경(`rgba(127,127,127,0.08)`)으로 전환 — personal-brand 히어로(16/10↔4/5)·벤토 갤러리, invitation 히어로 아치(3/4)·갤러리(1:1)·캐러셀(3/4), freelancer 포트폴리오(4/5)·벤토, small-biz 갤러리(4/3), cafe 갤러리(1:1). **배포 번들 5개 + 에디터 프리뷰 4개 파일 동시 수정**(2경로 함정). 원형 아바타·60px 메뉴 썸네일은 cover 유지(원 안에 직사각형 무손실 표시는 불가능 — 크롭 도구가 해결).
  - `validate-module-state.ts` URL 형식 검사에 image 타입 포함, `module-roundtrip.test.ts` mutateField에 image 케이스 추가.
- **검증:** typecheck 0 errors · 변경 파일 lint clean · 전체 vitest 379/379 통과(라운드트립 고정점·템플릿 무결성 포함).
- **인사이트:** `imageAspect`는 템플릿 CSS의 슬롯 비율과 **수동 동기화되는 계약**이다 — 템플릿 aspect-ratio를 바꾸면 스키마 힌트도 같이 갱신해야 크롭 프리셋이 실제 표시와 일치한다. 기존 배포 사이트는 에디터에서 "적용" 시 새 CSS로 재생성된다(이미 cover 기준으로 찍힌 샘플 이미지는 비율이 슬롯과 같아 시각 변화 없음).
- **미조치(보고):** 업로드 제한 불일치 — 클라이언트 5MB(원본 파일) vs 서버 2MB(base64 문자열, 실 바이너리 ~1.5MB). 리사이즈 후 WebP는 사실상 2MB를 넘지 않아 실사용 문제는 낮지만 정합화 필요. 업로드마다 `public/images/{ts}-upload.webp`가 사용자 repo에 누적되고 이전 파일 삭제가 없는 것도 기존 갭.
