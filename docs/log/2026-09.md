# 2026-09 작업 로그

### 2026-09-14 — 무료배포 자료를 DB로 이관, 관리자 화면에서 기존 템플릿으로 추가·발행
- **카테고리:** #기능 #인프라
- **중요도:** P1
- **지시:** "무료배포자료에 관리자로그인시 관리자가 배포자료 기존 템플릿활용해서 항목 추가하고 설정할수있는 기능 적용업데이트"
- **맥락:** 자료가 `src/data/resources/free-resources.ts` 배열에 하드코딩돼 있어 자료 1건 추가는 물론
  영상 ID 한 줄을 채우는 데도 배포가 필요했다. 영상마다 자료가 한 건씩 쌓이는 유입 채널로 쓰려면
  관리자가 코드 없이 항목을 다뤄야 한다.
- **결과:**
  - **M110 `free_resources`** 테이블 신설 — 발행분(is_published) anon SELECT + admin CRUD RLS,
    updated_at 트리거(M065 함수 재사용), 자료 1번 시드 이관(`ON CONFLICT DO NOTHING`). 데이터 SSOT가 코드 → DB.
    `free-resources.ts`는 표시 상수·URL 헬퍼만 남기고 타입은 `src/types/resource.ts`로 이동.
  - **`/admin/resources`** 목록·편집기 — 기존 자료와 같은 템플릿(히어로 · 복사용 지시문 블록 · 바로가기 ·
    배포본 · 마무리) 폼, 발행 스위치, 「템플릿으로 복제」(구성 복사 + slug·영상·발행만 비움),
    유튜브 URL 붙여넣기 → 11자 ID 추출, 다음 자료 번호 자동 제안.
  - **공개 페이지 ISR 전환** — `/resources`·`/resources/[slug]` `revalidate = 60`, `sitemap.ts`·`llms.txt` 3600.
    쿠키 없는 anon 클라이언트(`src/lib/supabase/public.ts`)로 읽어 정적 캐시를 유지. sitemap·llms.txt는
    DB 실패 시 자료 엔트리만 비우고 나머지는 정상 생성.
  - **빌드 시점 DB 의존 발견** — `/resources`는 정적 경로라 `next build`가 프리렌더하며 라이브 DB를 조회한다.
    M110 미적용 상태의 첫 빌드가 "table not found"로 실패해 확인됨. `NEXT_PHASE === 'phase-production-build'`
    에서만 빈 목록 폴백(첫 요청 후 ISR이 채움), 런타임은 throw 유지(빈 페이지 캐시 대신 직전 캐시본 서빙).
  - **관리자 진입점** — 관리자 로그인 시 `/resources`·상세 상단에 관리자 바(새 자료 추가 · 자료 관리 · 이 자료 편집).
    ISR 캐시에 섞이지 않도록 클라이언트에서 본인 `profiles.is_admin`을 읽어 판정(header.tsx와 같은 방식).
  - **API** `/api/admin/resources[/id]` — getUser → isAdmin → Zod safeParse → RLS → logAudit 5단계,
    감사 액션 `admin.resource_{create,update,delete}` + 메뉴 사전 등록. 쓰기는 user-scoped 클라이언트
    (RLS `admin_full_access`가 실효 방어선), `createAdminClient()`는 쓰지 않음. slug 중복 23505 → 409.
  - 테스트 23건(라우트 401→403→400→404→201/200→audit, Zod 경계) · typecheck · lint 통과.
- **인사이트:** `revalidatePath`는 OpenNext tagCache 미설정으로 동작하지 않아 시간 기반 ISR만 택했다 —
  "저장 후 1분"이 운영 규약이고 관리자 UI 문구에도 그대로 박았다. 관리자 편집기는 공개 페이지에 섞지 않고
  `/admin` 아래 두되 진입점만 공개 페이지에 심는 구조가 정적 캐시·번들 크기 모두에 유리했다.
  미해결: 오프라인 배포본 HTML은 여전히 `public/downloads/`에 수동 커밋해야 한다(DB 데이터로 자동 생성은 후속).

### 2026-09-14 — 무료배포 자료 2번 「듀얼모니터 간편설정」 발행 준비 (REQ-0008)
- **카테고리:** #기능 #콘텐츠
- **중요도:** P1
- **지시:** "듀얼모니터 화면설정·세팅방법을 웹에서 검색해, HTML에서 버튼만 클릭하면 해당 설정 페이지가 열리는
  매뉴얼형 페이지를 기획해 무료배포자료 2로 만들어줘 — 목적은 듀얼모니터 사용자를 위한 간편설정 페이지"
- **맥락:** 자료 1(엑셀 취합기) 이후 두 번째 자료. "영상마다 자료 한 건" 채널의 2호로, 자료 1과 달리 복사용
  지시문이 아니라 **OS 설정 화면을 직접 여는 인터랙티브 안내서**라 오프라인 배포본 HTML이 본체다.
  같은 시각 다른 세션이 M110(자료 DB 이관·관리자 화면)을 미커밋 상태로 작업 중이어서, 그 세션 파일은
  건드리지 않고 신규 파일 + 1줄 추가로만 구성했다.
- **결과:**
  - `public/downloads/dual-monitor-setup.html` — 외부 요청 0건 단일 파일(72KB). 공식 URI 스킴 `ms-settings:`
    9종으로 Windows 설정 화면을 바로 열고, macOS는 `x-apple.systempreferences:` 3종. 빠른 시작 3단계(체크 상태
    localStorage) · 설정 카드 10장(수동 경로·단계·Windows 10 차이 접기) · 단축키 12개 · 문제 해결 8건 ·
    Win+R 명령 표(행별 복사) · macOS 섹션 · 참고 링크. OS 감지로 배지·버튼을 분기하고, 클릭 시
    "브라우저 확인창에서 [열기]" 힌트, 인쇄 시 접힌 항목 자동 펼침. 자료 1 골격·토큰·로고·역링크 규약 승계.
  - DB 행: `docs/db-uploads/2026-09-14_free_resources_dual-monitor-setup.sql`(gitignore) — 같은 데이터를
    `createResourceSchema.safeParse`로 검증한 뒤 생성. 복사 블록 1개(Win+R 명령 모음), primary 링크 = 배포본
    새 탭, `checklist` 카테고리, 영상 준비 중. **Supabase MCP로 migration 110 적용 후 시드 실행 완료**
    (free_resources 2행, RLS·정책·트리거 반영, security advisors에 신규 경고 없음).
  - `scripts/warm-cache.sh`에 `/resources/dual-monitor-setup` 추가 — M110 코드 배포 전엔 404로 워밍업이 실패하므로
    그 커밋과 함께 올린다(배포본 HTML만 먼저 커밋·푸시, dbb869d9).
  - 상세 템플릿 고정 문구("이 자료의 도구도 Linkmap으로…", "무료 플랜…")를 `/sites/new` primary일 때만 표시하고
    external primary는 새 탭 `<a>`로 렌더하도록 수정 — 같은 파일을 M110 세션이 작업 중이라 패치로 준비해 두었다가
    그 커밋(cae1e6a7) 직후 적용(typecheck·lint·vitest 35/35 통과).
  - 검증: 정적(외부 리소스 참조 0 · 로고 data URI 1회) · Playwright(네트워크 요청 = 문서 1건, 콘솔 오류 0 —
    브라우저 favicon 자동 요청 제외, 400px 가로 스크롤 없음, 체크 상태 새로고침 유지, 힌트·복사 동작) ·
    이 PC(Windows 11 25H2)에서 `ms-settings:display` 실행 확인.
- **인사이트:** 웹 리서치의 함정은 **MS 지원 한국어 페이지가 기계번역**이라 실제 UI 표기와 다르다는 점
  ("표시"→"디스플레이", "검색"→"감지"). 국내 실측 가이드로 교차 확인해 라벨을 정했다. `ms-settings:display-advanced`는
  Windows 11에서 디스플레이 페이지로만 열려 "아래로 내려 고급 디스플레이" 문구를 병기했다. 이 PC는 UI 언어가
  en-US라 스크린샷으로 한글 라벨을 실측할 수 없었다 — 미확정 라벨(모니터별 배경 우클릭 메뉴 등)은 배포 후
  한국어 Windows에서 1회 확인이 필요하다.
