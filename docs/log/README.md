# Prompt Log System

## 목적
프로젝트 진행 중 지시한 프롬프트, 맥락, 의사결정을 경량 로그로 기록.
이후 분석·기획·회고의 전략적 자산으로 활용.

## 구조
```
docs/log/
  README.md        ← 이 파일 (가이드)
  milestone.md     ← 프로젝트 주요 전환점 (백필)
  2026-04.md       ← 월별 로그 (현재)
  2026-05.md       ← (다음 달 자동 생성)
```

## 로그 엔트리 포맷
```markdown
### YYYY-MM-DD — 제목
- **카테고리:** #태그
- **중요도:** P0/P1/P2
- **지시:** 한 줄 요약
- **맥락:** 왜 이 작업을 요청했는지 (1~2문장)
- **결과:** 무엇이 완료/변경되었는지
- **인사이트:** (선택) 기획적 시사점, 방향 전환, 학습
```

## 카테고리 태그
| 태그 | 설명 |
|------|------|
| `#기획` | 방향 설정, 전략 변경, 우선순위 조정 |
| `#기능` | 신규 기능 개발, 기능 확장 |
| `#버그` | 버그 수정, 장애 대응 |
| `#리팩터` | 코드 정리, 구조 개선 |
| `#디자인` | UI/UX, 디자인 시스템 |
| `#인프라` | 배포, 성능, 보안, DB |
| `#콘텐츠` | 블로그, 가이드, SEO |
| `#분석` | 벤치마킹, 경쟁사 분석, 데이터 분석 |

## 중요도
| 등급 | 기준 | 예시 |
|------|------|------|
| **P0** | 전략적 전환점, 핵심 의사결정 | 타겟 변경, 아키텍처 전환 |
| **P1** | 주요 기능/방향성 결정 | 신규 기능 도입, 대형 리팩터 |
| **P2** | 일반 작업, 유지보수 | 버그 수정, 소규모 개선 |

## 기록 기준
**기록한다:**
- 새로운 방향 설정이나 전략 변경
- "왜"가 명확한 의사결정
- 시행착오에서 얻은 인사이트
- 반복 패턴이 보이는 작업

**기록하지 않는다:**
- 단순 타이포 수정
- 이미 커밋 메시지로 충분한 작업
- 코드 레벨 디테일 (diff/snippet)

## 활용
- **월간 회고**: 월말에 해당 월 로그 스캔 → P0/P1 엔트리 중심 회고
- **기획 참조**: 새 기능 기획 시 관련 태그 검색으로 과거 맥락 파악
- **패턴 분석**: 카테고리별 빈도로 개발 흐름 파악
