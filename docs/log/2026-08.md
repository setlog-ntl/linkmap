### 2026-08-19 — 정적 배포본이 자료 상세 라우트를 가리던 문제 수정
- **카테고리:** #버그 #인프라
- **중요도:** P1
- **지시:** "영상·최신본 확인 항목을 자료 페이지 가장 하단으로 위치 수정"
- **맥락:** 위치 조정 요청을 확인하러 라이브를 열었더니, 사용자가 보고 있던 화면이
  **Next.js 자료 페이지가 아니라 오프라인 배포본 HTML**이었다. `/resources/excel-merger-prompt`와
  `/resources/excel-merger-prompt.html`이 동일한 28,584바이트를 반환 — 정식 URL이 가려져 있었다.
- **결과:**
  - 원인: Workers는 `public/` 정적 자산을 라우트보다 먼저 매칭하고 `.html`을 확장자 없이도
    서빙한다. `public/resources/excel-merger-prompt.html`이 `/resources/[slug]`를 통째로 가림.
    허브에서 「자료 보기」를 누르면 헤더·푸터·내려받기·마무리 CTA가 전부 없는 배포본이 열렸다.
  - 수정: 배포본을 `public/downloads/`로 격리해 `/resources/` 네임스페이스를 라우트 전용으로 비움.
    `downloadHref`·문서·`FreeResource` 타입 주석에 재발 방지 규약 명시.
  - 함께: 요청대로 배포본의 「영상·최신본 확인」 역링크 카드를 본문 아래 푸터 직전으로 이동
    (히어로 → 지시문1 → 지시문2 → 역링크 → 푸터). aitube 사본도 동기화.
- **인사이트:** **로컬 `next dev`에서는 재현되지 않는다.** dev 서버는 라우트를 먼저 매칭하지만
  Workers assets는 반대다. `npm run build` 로그에 `● /resources/[slug]`가 정상 출력돼도
  실제로는 도달 불가였다 — 빌드 성공이 라이브 도달 가능을 뜻하지 않는다. 공개 페이지는
  **배포 후 라이브 URL로 한 번은 실제 응답을 확인**해야 한다.
