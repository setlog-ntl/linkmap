# 2026-08 작업 로그

### 2026-08-01 — 나만의 엑셀자동화: 도구를 파일 하나로 저장(오프라인 사용) 기능 추가
- **카테고리:** #기능
- **중요도:** P1
- **지시:** "내 컴퓨터에 저장기능 추가해서 로컬에서 사용할 수 있게 업데이트"
- **맥락:** 이 템플릿의 핵심 약속이 "회사 파일이 밖으로 안 나간다"인데, 엑셀 엔진을 CDN에서
  받는 구조라 **CDN이 막힌 사내망에서는 도구가 아예 안 돌았다**(07-31 감사 P1). 019 영상은
  이미 오프라인 단일 HTML을 리드마그넷으로 쓰고 있어, 같은 것을 배포 산출물이 스스로 만들게 했다.
- **결과:**
  - `src/lib/standalone.ts`(신규 번들 파일) — 저장 시점에 SheetJS를 받아 HTML에 통째로 인라인한
    단일 파일을 생성. 도구 UI 상단에 "이 도구를 내 컴퓨터에 저장" 버튼 추가. 미리보기에도 반영.
  - 저장본은 **외부 요청 0건**(script/link/img src 전무, 내 코드 영역에 fetch·XHR·http 전무) —
    인터넷 없이, 외부 연결이 막힌 PC에서도 열린다. 취합 엔진은 온라인본과 동일 로직.
  - **함정 실측:** 처음엔 실제 함수를 `toString()`으로 직렬화해 심었는데 번들러 헬퍼(esbuild
    `__name`)가 딸려 나와 저장본이 `ReferenceError`로 즉사. `String.raw` 원문 문자열로 전환해 해결.
  - 검증: materialize→`tsc --noEmit` 통과(하네스 오탐 1건 제외, 미변경 템플릿도 동일) ·
    Playwright로 019 샘플 6종 실투입 → **52행·11열**, 「확인이 필요한 것」 4종 발화, 내려받은
    xlsx의 금액 52칸 전부 숫자(합계 813,069,100) — 019 문서의 정답과 일치. vitest 151/151.
- **인사이트:** 번들 파일 내용은 전부 문자열이라 linkmap의 tsc·eslint·vitest가 **전혀 검사하지
  않는다.** 게다가 템플릿은 eslint만 무시하고 타입 오류는 빌드를 깨므로, 번들 파일을 손대면
  materialize 후 별도 타입검사가 사실상 필수다(방법은 memory/oneclick-build-verification.md).
