# 2026-06 작업 로그

### 2026-06-11 — 원클릭 배포 안정화·하드닝 (빌드 재현성 + 엔드포인트 강건화)
- **카테고리:** #인프라 #버그 #리팩터
- **중요도:** P1
- **지시:** 원클릭 배포의 배포→점검→재배포 전 과정을 디테일하게 점검·분석하여 문제를 도출하고, 안정화 및 안정성 보강 기획·구현.
- **맥락:** 원클릭 배포는 2층 퍼널의 1층 진입점(바이브코더 첫 경험)인데, "오늘 되던 배포가 내일 깨진다"류의 재현 불가능·관측 곤란 문제가 잠재. 코드 직접 검증으로 실제 이슈와 오탐(고아 프로젝트·무한 폴링 2건)을 분리한 뒤 구조적으로 보강.
- **결과:**
  - **WS1 빌드 재현성(P0)**: 템플릿 번들에 lockfile 부재 + `deploy.yml`의 `npm install` → transitive 부유로 빌드 비결정성. 의존성 세트별 lockfile 2종(standard/namecard) 생성(`scripts/gen-template-lockfiles.mjs`, `src/data/oneclick/locks/`), `makePackageLock()` 헬퍼로 8개 템플릿 번들에 `package-lock.json` 주입, `deploy.yml`을 `npm ci`로 전환. 드리프트 가드 테스트(`template-deps.test.ts` 16건)와 `npm ci` 실증 검증 스크립트(`verify-template-lockfiles.mjs`) 추가. 기존 배포 레포는 deploy.yml 동결로 무영향(무중단).
  - **WS2 엔드포인트 하드닝(P0/P1)**: `deploy/route.ts` 리소스 생성 순서를 GitHub(레포·Pages·푸시) 먼저 → DB(프로젝트·SA·배포레코드) 마지막으로 재배치 → 중도 실패/요청 중단 시 고아 DB row 미발생. 이름충돌 재시도 31→8회 축소 + 150~400ms 지터 백오프 + 20s 누적 예산(게이트웨이 타임아웃·GitHub 2차 rate-limit 회피).
  - **WS3 구조화 에러 코드(P1)**: `apiErrorWithCode` 추가, 배포 실패 응답에 안정적 `code`(=로깅 카테고리) 포함, 클라 `deploy-error-map`이 문구 substring 대신 code 우선 매핑.
  - **WS4 타임아웃·폴링(P1)**: `deploy-status.ts` 타임아웃을 **GitHub 실제 상태 우선**으로 재구성 — 상태를 확인한 뒤 여전히 building일 때만 `updated_at` 기준 15분 무진전으로 에러 판정(혼잡한 러너로 15분 넘겨 성공한 빌드를 잘못 실패시키지 않음). `useDeployStatus` 하드 폴 캡·연속 실패 캡 추가. (※ 초기 검토 시 추가했던 `created_at` 절대 상한은 "60분 이상 된 배포 재배포 시 즉시 타임아웃" 버그라 제거.)
  - **WS5 무결성(P2)**: `validateModuleState`에 minLength/maxLength·number min/max·email·url(관대)·maxItems 검증 활성화. `template-integrity.test.ts`에 생성 코드 구문 검증 + default 상태 검증 안전성 추가. 안전성 테스트가 link-card `emoji` 필드(아이콘 키를 담는데 maxLength:4) 사전 불일치를 적발→교정.
  - 검증: typecheck/lint(에러 0) 통과, oneclick 테스트 68건 통과. env/mfa 관련 사전 실패 15건은 본 작업과 무관(stash 대조 확인).
  - **범용성 검증(임의 로그인 유저 관점)**: 병렬 감사 2건으로 (a) 계정/스코프/워크플로우 범용성 — OAuth 스코프(repo/workflow) 적절, `createRepo` public 기본(무료 계정 Pages 가능), `/user/repos`로 항상 개인 계정 생성, Actions 워크플로우 요건(permissions/build_type:workflow) 충족 확인. (b) 재배치된 deploy 흐름·이름채번·폴링·에러코드·재배포 정합성 확인. 발견된 실제 이슈를 추가 수정: ① 타임아웃 상태우선 재구성(위), ② **배포 전 workflow 스코프 사전 검증** 추가(좁은 스코프 계정의 고아 레포+늦은 403 방지), ③ **배포 quota 원자화** — migration 052의 `check_homepage_deploy_quota`는 count-only라 check↔INSERT가 별도 트랜잭션이면 advisory lock이 먼저 해제돼 동시 배포 시 한도 초과 가능했음. migration 098 `create_homepage_deploy_atomic` RPC로 advisory lock 하의 단일 트랜잭션에서 count+INSERT를 묶어 진짜 원자성 확보(SECURITY DEFINER+auth.uid()+프로젝트 소유권 검증). deploy route의 최종 insert를 이 RPC로 교체, 한도 초과 시 GitHub 레포 정리 후 quota 에러. 미해결 항목(후속): GitHub 토큰 refresh 미구현(현 OAuth App은 만료 없어 무영향).
  - **빌드 범용성 실증**: 8개 템플릿 번들을 디스크로 추출해 GitHub Actions와 동일한 `npm ci && next build`(static export)를 **WSL/Linux(=ubuntu)** 에서 실행해 산출물 빌드 검증(`scripts/materialize-template.ts`, `.bt/build-wsl.sh`). Windows 로컬은 `@vercel/og` `fileURLToPath` 이슈로 OG 라우트 프리렌더 불가(환경 한정, ubuntu 무관) → Linux 검증으로 우회.
- **인사이트:** Explore 보고의 P0 주장 2건(고아 프로젝트·무한 폴링)이 코드 직접 검증 결과 오탐으로 판명 — 에이전트 발췌 보고는 반드시 원본 검증 후 채택. lockfile은 의존성 세트가 다르면(`qrcode.react`) 단일 공유 불가, 세트별 관리 필요. "default 상태는 형식 검증을 통과해야 한다"는 불변식 테스트가 검증 강화의 안전망이자 잠재 스키마 버그 탐지기로 동작.
