### 2026-06-13 — 무료 플랜 제한 점검 + 원클릭 배포 한도 표시·쿼터 정합성 보강
- **카테고리:** #기능 #인프라 #디자인
- **중요도:** P1
- **지시:** 무료 플랜 기본 적용 기능 제한과 원클릭 배포 갯수 제한 적용을 확인하고, 발견한 갭을 추가·반영.
- **맥락:** 원클릭 배포는 2층 퍼널 1층 진입점. 무료 한도(배포 3)는 코드/DB(`quota.ts`·`plan_quotas`·`create_homepage_deploy_atomic` RPC)로는 강제되지만 가격 페이지에 노출되지 않아 사용자가 차단 시점에서야 한도를 인지하는 마찰이 있었고, 원자적 RPC의 구독 상태 필터가 앱 레벨과 어긋나 있었음.
- **결과:**
  - **무료 제한 확인**: 프로젝트 3 / 환경변수 20·project / 서비스 10·project / 팀원 0 / **원클릭 배포 3** (Pro 10, Team 50, Admin 무제한). 배포 한도는 사전 체크(`checkHomepageDeployQuota`) + advisory lock 하 원자적 check-and-insert(`create_homepage_deploy_atomic`, M098~100)로 race까지 차단됨을 확인.
  - **Gap 1 — 가격 페이지 표시**: `pricing-content.tsx`에 플랜별 `deployLimit`(3/10/50) 필드 추가, 기능 목록 최상단에 "원클릭 배포 N개" 라인 렌더. i18n 동결 규칙 준수 위해 json 키 미추가 — 컴포넌트 내 양 로케일(ko/en) 리터럴로 처리.
  - **Gap 2 — RPC 쿼터 정합성(M101)**: `create_homepage_deploy_atomic`·`check_homepage_deploy_quota`·`check_project_quota`의 구독 필터를 `status = 'active'` → `status IN ('active','trialing')`로 정렬(앱 레벨 `quota.ts`의 `.in('status',['active','trialing'])`와 일치). trial 중 Pro/Team 사용자가 배포 RPC 경로에서 free 한도(3)로 잘못 차단되던 불일치 해소. 관리자 바이패스(M100)·enum 캐스트(M099)·권한 유지.
  - 검증: typecheck 통과. M101은 DB 적용 대기.
- **인사이트:** "한도를 강제하는 곳"과 "한도를 알리는 곳"이 분리되면 사용자는 차단당해서야 정책을 학습한다 — 진입 퍼널일수록 한도는 사전 노출이 마찰을 줄인다. 또한 동일 정책(구독 상태·관리자 바이패스)이 앱 레벨과 RPC 두 곳에 중복 구현되면 한쪽만 수정되어 드리프트가 생기므로, 쿼터 판정 기준은 단일 소스화가 바람직.

### 2026-06-12 — 환경변수/API 키 관리 심플 전면 개편 (검증=저장 후 옵션, 메모장형 UX)
- **카테고리:** #기능 #디자인
- **중요도:** P1
- **지시:** API 키/환경변수 관리를 메모장처럼 쉽게 입력·복사·전체 보기 가능하게, 키 검증은 저장 이후 옵션으로 분리, 형식 차이로 저장이 거부되지 않게 심플 우선 전면 개편 (보안은 유지).
- **맥락:** 서비스마다 키 형식이 달라 저장 시점 형식 검증이 초보자(바이브코더) 진입을 막는 마찰 지점이었음. "일단 저장은 무조건 성공 → 검증은 선택" 으로 철학 전환.
- **결과:**
  - **키 정규화(거부→자동 정리)**: 신규 `src/lib/utils/env-key.ts` (`normalizeEnvKey`/`ENV_KEY_REGEX`). Zod 스키마(`validations/env.ts`의 `envKeyNameSchema`)가 `transform`으로 정규화 — 소문자/특수문자/숫자 시작 키도 거부 없이 저장됨. create/update/bulk/raw 4개 경로 + `parse-env.ts` 파서 모두 동일 규칙 공유 (숫자 시작 키가 파싱에서 버려지던 문제도 해소).
  - **전체 보기/전체 복사**: `/api/env/decrypt`에 `{ ids[] }` 일괄 복호화 추가 (MFA 가드·소유권 필터·`env_var.bulk_decrypt` 감사 로그 유지, 최대 200개). 필터바에 "모든 값 표시/숨기기" 토글 + "전체를 .env 형식으로 복사" 버튼. 테이블에서 표시된 값은 줄바꿈 전체 표시 + 클릭 시 복사.
  - **검증=저장 후 옵션**: 저장 성공 토스트에 "지금 검증" 액션(서비스 연결 시), 행 메뉴에 "연결 검증 (선택)" — 기존 health-check API 재사용. 검증 실패해도 저장값 유지 안내.
  - **다이얼로그 심플화**: 추가/수정 모두 이름+값만 핵심 노출, 설명·서비스·환경·Secret은 "상세 설정" 접기. 값 입력 Input→Textarea (여러 줄 PEM 키 지원). 자동 서비스 감지 배지는 비침투 유지.
  - **보안 불변**: 암호화(AES-256-GCM)·MFA 가드·감사 로그·소유권 확인·NEXT_PUBLIC 경고 전부 유지. 복호화 실패 silent catch → 토스트로 교체.
  - 검증: typecheck/lint 통과, decrypt 테스트 12건(일괄 포함) 통과. 사전 실패였던 env decrypt/download 테스트(MFA mock 누락·영문 메시지 기대)도 수리. service-accounts 3건 실패는 본 작업과 무관(stash 대조 확인).
- **인사이트:** "형식 검증으로 입력을 막는 것"과 "보안"은 별개 축 — 검증을 빼도 암호화·감사·MFA는 그대로라 보안 저하 없음. 서버가 거부 대신 정규화(transform)하는 패턴은 클라이언트·API 직접 호출 모두에서 입력 실패율을 0에 수렴시킴.

### 2026-06-11 — 원클릭 배포 안정화·하드닝 (빌드 재현성 + 엔드포인트 강건화)

- **중요도:** P1
- **지시:** 원클릭 배포의 배포→점검→재배포 전 과정을 디테일하게 점검·분석하여 문제를 도출하고, 안정화 및 안정성 보강 기획·구현.
